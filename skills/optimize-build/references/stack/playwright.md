# playwright — optimize-build stack reference
Use when: detect-stack.sh reported `playwright`. Lanes: test, cache.

Checked 2026-11-09 against `@playwright/test` **1.65.0** (released 2026-11-05): source at the `v1.65.0` tag, docs and release notes. **(local)** means run that day with 1.65.0 (macOS, Node 24.22/26.8, OrbStack Docker), so re-measure on the repo. **(inferred)** means reasoned from docs or source, not measured. Read the repo's version first: `npm ls @playwright/test`, plus the image tag in any `container:`. General worker and shard theory is in `test-parallelism.md`. Generic E2E cost is in `test-environment.md`.

## Measure
- **Workers actually used.** The first line of every run is `Running N tests using M workers[, shard i of n][, shuffle seed S]`. M = min(configured workers, test groups in the largest phase) ([tasks.ts](https://github.com/microsoft/playwright/blob/v1.65.0/packages/playwright/src/runner/tasks.ts)). M below the configured count means there are too few schedulable groups (whole files, without `fullyParallel`).
  `gh run view <id> --log | perl -pe 's/\e\[[0-9;]*m//g' | grep -E 'Running [0-9]+ tests? using|Slow test file'`
- **Phases.** `DEBUG=pw:test:task npx playwright test` timestamps each runner task: `plugin setup` (this is the `webServer` boot), `global setup`, `load tests`, `create phases` (it logs `created phase #k with … N testGroups`) and `test suite`. `DEBUG=pw:webserver` adds `Starting WebServer process` → `WebServer available`. These are internal debug namespaces, not a documented API (local).
- **Slow files.** `reportSlowTests` has defaulted to `{ max: 5, threshold: 300_000 }` since **1.51**; through 1.50 the threshold was 15 000 ms. On 1.51+ it is therefore usually silent. Set `{ max: 0, threshold: 60_000 }` to list every file over 60 s ([TestConfig](https://playwright.dev/docs/api/class-testconfig)). The output is `Slow test file: <file> (<dur>)`. **It counts only files whose tests all ran in one worker** ([base.ts](https://github.com/microsoft/playwright/blob/v1.65.0/packages/playwright/src/reporters/base.ts)), so under `fullyParallel` a slow file split across workers is never listed (local).
- **Per-file time and real concurrency (JSON).** Run `PLAYWRIGHT_JSON_OUTPUT_NAME=pw.json npx playwright test --reporter=json`. On 1.63+, `--add-reporter=json` keeps the configured reporters. Each result carries `workerIndex`, `parallelIndex`, `retry`, `duration` and `startTime`, and `stats.duration` is wall-clock ms ([testReporter.d.ts](https://github.com/microsoft/playwright/blob/v1.65.0/packages/playwright/types/testReporter.d.ts)). Both queries tested on 1.65.0:
  ```bash
  jq -r '[.suites[] | {file, ms: ([.. | objects | select(has("workerIndex")) | .duration] | add)}] | sort_by(-.ms)[:25][] | "\(.ms/1000)s\t\(.file)"' pw.json
  jq '([.. | objects | select(has("workerIndex")) | .duration] | add) as $b | {busy_s: ($b/1000), wall_s: (.stats.duration/1000),
      avg_concurrency: ($b/.stats.duration), retry_s: (([.. | objects | select(has("workerIndex") and .retry > 0) | .duration] | add // 0)/1000), flaky: .stats.flaky}' pw.json
  ```
  If `avg_concurrency` is well below M, workers sit idle: a long-tail file, or serial groups. Under `fullyParallel`, per-file sums are **worker time, not wall time**. For sharded runs, merge first (`PLAYWRIGHT_JSON_OUTPUT_NAME=pw.json npx playwright merge-reports --reporter json ./all-blob-reports`, local) and take each shard's wall time from the CI API, not from `stats.duration`.
- **Timeline.** On 1.63+, `--add-reporter=perfetto` writes `test-results/perfetto.json` (gzipped if the name ends in `.gz`). It has one lane per worker, with each test as a slice and its hooks, fixtures and steps nested ([reporters](https://playwright.dev/docs/test-reporters)). Open it in ui.perfetto.dev. Gaps mean imbalance; wide fixture or hook slices mean setup cost. The HTML report has a Speedboard tab that "shows you all your executed tests sorted by slowness" (1.57+), a Timeline for merged reports (1.58+) and a step-duration waterfall (1.63+).
- **JUnit** (for the lane's generic ranking): `PLAYWRIGHT_JUNIT_OUTPUT_NAME=results.xml npx playwright test --reporter=junit`.
- **Install and pull cost.** Look at the `npx playwright install …` step, and at `Initialize containers` for `container:` jobs. `npx playwright install --dry-run [--only-shell] chromium` lists exactly what would download.
- **CPUs the runner reports:** `node -p 'os.cpus().length + " " + os.availableParallelism()'` inside the job.

## Checks
**1. Workers pinned to 1, or set without measuring.** **Check** `rg -n "workers\s*:" playwright*.config.*`, the `using M workers` line, and the runner's vCPUs (`test-parallelism.md` §1.1). **Good** M ≈ the cores the job really has. On 2 vCPU the default (`'50%'`) already gives 1, so the only levers there are a larger runner or sharding.
**Fix** Drop `workers: process.env.CI ? 1 : undefined`. create-playwright stopped generating it on 2026-02-12 ([PR #170](https://github.com/microsoft/create-playwright/pull/170)), but the [CI guide](https://playwright.dev/docs/ci) still recommends 1 "to prioritize stability and reproducibility". Alternatively set a number. A percent string floors `cpus × p` with no cap (`'200%'` works). Per-project `workers` (1.52+) still sits under the global cap.
**Gain** Up to M× on the test step if tests are not CPU-bound (heuristic). Confirm with `avg_concurrency`. **Risk** Each worker runs its own browser, so workers × per-worker RSS must fit in RAM. CPU starvation shows up as timeouts, so prove stability with `--shuffle --repeat-each=3` (1.64+) before merging.

**2. Container CPU quota counted as host CPUs.** **Check** On self-hosted, ARC/k8s or `docker --cpus` runners, compare `os.cpus().length` with `os.availableParallelism()` in the job. **Good** The two numbers match (GitHub-hosted VMs), or `workers` is explicit.
**Fix** `--workers=$(node -p 'os.availableParallelism()')` (it honours cgroup quotas on Node ≥22.12, see `test-parallelism.md` §1.1), or the quota as a number.
**Gain** Ends oversubscription. `'50%'` resolves via `os.cpus().length` ([config.ts](https://github.com/microsoft/playwright/blob/v1.65.0/packages/playwright/src/common/config.ts)). (local) On an 18-CPU host under Docker `--cpus=2` and under `--cpuset-cpus=0,1`, `os.cpus().length` = 18 while `availableParallelism()` = 2 (Node 24.22.1 and 26.8.1). That is 9 workers on 2 CPUs. Node's own docs say not to use `os.cpus().length` for parallelism ([os](https://nodejs.org/api/os.html#oscpus)). **Risk** A hard-coded number goes stale when the runner is resized.

**3. Files serialised (`fullyParallel` off).** **Check** `rg -n "fullyParallel|mode:\s*['\"](serial|default)" playwright*.config.* e2e tests`, `testGroups` < workers in `DEBUG=pw:test:task`, or one file dominating the per-file jq. **Good** `fullyParallel: true` (the create-playwright default), with opt-outs via `test.describe.configure({ mode: 'default' })`. Without it, files run in parallel but the tests inside a file run in order in one worker.
**Fix** Enable it. Guard shared resources with test locks, which never overlap across files, workers or projects while everything else stays parallel: `{ lock: 'name' }` (1.63+), `describe.configure({ lock })` (1.64+), or the built-in `-exclusive-` lock (1.65+) to run a test alone. In default and serial mode, a lock on any test is held for the whole file, so locks need `fullyParallel` ([parallel](https://playwright.dev/docs/test-parallel)). The docs call `mode: 'serial'` "not recommended": after a failure it skips the rest of the group and retries the whole group.
**Gain** Removes the long-file tail, and shards balance per test instead of per file (typical, unmeasured). **Risk** In parallel mode, "each test executes all relevant hooks just for itself, including `beforeAll` and `afterAll`", so an expensive file-level `beforeAll` now runs once per test. Run `rg -l beforeAll` first. Hidden in-file order dependencies surface: run `--shuffle`.

**4. No sharding, or unbalanced shards.** **Check** There is no `--shard` even though M already equals the job's cores and the test step is ≥3× per-job setup (`test-parallelism.md` §7). Or per-shard test steps differ by more than ~1.3× (heuristic). **Good** A matrix running `--shard=${{ matrix.shardIndex }}/${{ matrix.shardTotal }}` with `fail-fast: false` and `reporter: process.env.CI ? 'blob' : 'html'`. Each shard uploads `blob-report/`. A merge job with `needs:` and `if: ${{ !cancelled() }}` runs `npx playwright merge-reports --reporter html ./all-blob-reports` ([sharding](https://playwright.dev/docs/test-sharding)).
**Fix** Set it up as in Good, with `fullyParallel`. Without it, whole files are assigned, and "the same file may be assigned to different shards across different projects".
**Gain** At most N× the test step, minus N × setup (heuristic). **Risk** Shards balance on test count, never duration, and statically skipped tests are not counted. Every shard repeats the install, browser install, app build and `webServer` boot. From 1.65, a run whose shards match no tests fails unless you pass `--pass-with-no-tests`. Blob zips carry traces and screenshots, so artifact size grows with the trace settings.

**5. `webServer` builds the app, or runs a dev server, inside the test step.** **Check** `rg -n -A6 "webServer" playwright*.config.*`: `command` contains `build &&`, `next dev`, `vite` (not `preview`) or `npm run dev`. Measure boot time with `DEBUG=pw:webserver`. **Good** The app is built once in its own cached step (or in one build job whose output every shard downloads), then `command: 'npm run start'` / `vite preview`, `url:` (`port` is deprecated), `reuseExistingServer: !process.env.CI`, and `timeout` (default 60000 ms) sized to the real boot. On 1.57+, use `wait: { stdout: /…/ }` when the server logs readiness but has no cheap URL ([webServer](https://playwright.dev/docs/test-webserver)).
**Fix** Move the build out of `command` and point `command` at the production server. Next.js: "We recommend running your tests against your production code" (its stated reason is fidelity) ([Next.js](https://nextjs.org/docs/app/guides/testing/playwright)).
**Gain** Saves the build time on every shard. The dev-server cost is inferred: each test gets a fresh "incognito-like" context ([contexts](https://playwright.dev/docs/browser-contexts)), so the HTTP cache is cold and the dev server's unbundled module graph is refetched on each test's first navigation (typical, unmeasured). **Risk** Tests may depend on dev-only behaviour (dev env vars, mocks). By default the server process group is `SIGKILL`ed; `gracefulShutdown` (1.50+) changes that.

**6. UI login in every test.** **Check** `rg -n "goto\(['\"]/login|fill\(.*password" -g '*.{spec,test}.*'` inside `beforeEach`, or login steps visible in perfetto/JSON. **Good** A `setup` project, with `dependencies: ['setup']` and `use.storageState: 'playwright/.auth/user.json'` (gitignored). Log in through the API: `request.post`, then `request.storageState({ path })` ([auth](https://playwright.dev/docs/auth)). Setup projects beat `globalSetup` because they get traces, fixtures and HTML-report entries ([global setup](https://playwright.dev/docs/test-global-setup-teardown)). Seed data through `request` as well, since it can "prepare server state" ([API testing](https://playwright.dev/docs/api-testing)).
**Fix** For tests that mutate server state, use one account per worker: a worker fixture keyed on `test.info().parallelIndex` (`TEST_PARALLEL_INDEX`), which is stable at 0..workers−1. `workerIndex` (`TEST_WORKER_INDEX`) changes after every worker restart. The same key works for any per-worker resource, such as a tenant or a database.
**Gain** (login time × tests) − one login per project or worker. Typical, unmeasured: take the login time from the JSON steps. **Risk** Tokens in IndexedDB need `storageState({ indexedDB: true })`. sessionStorage is never saved. Stale state must be deleted when it expires.

**7. Third-party and asset traffic.** **Check** Traces or perfetto show long `goto`/load waits, with requests going to analytics, fonts, maps or other third parties. **Good** Third parties are mocked with `route.fulfill` ([best practices](https://playwright.dev/docs/best-practices)), and junk is aborted, e.g. `page.route('**/*.{png,jpg,jpeg}', r => r.abort())`, or by `route.request().resourceType()` ([network](https://playwright.dev/docs/network)).
**Fix** Override the `context`/`page` fixture to install the routes for every test.
**Gain** Typical, unmeasured: measure before and after. **Risk** "Enabling routing disables http cache" ([page.route](https://playwright.dev/docs/api/class-page#page-route)). Handlers run in the test process, so each matched request pays a round trip (inferred). Service Workers (MSW in the browser) bypass routing, so set `serviceWorkers: 'block'`. Never block assets in visual or screenshot tests.

**8. Browsers over-installed.** **Check** `rg -n "playwright install" .github/workflows`. Look for no browser argument (installs every browser), for `chromium` without `--only-shell` when no project sets `channel` or runs headed, and for installs in jobs that run no E2E. **Good** `npx playwright install --with-deps --only-shell chromium` (1.49+) for default headless runs. `channel: 'chromium'` (new headless) needs `--no-shell` instead ([browsers](https://playwright.dev/docs/browsers)). "Only install the browsers that you actually need" ([best practices](https://playwright.dev/docs/best-practices)).
**Gain** (local) For Chrome for Testing 158 on linux64, the full Chrome is 207 MB and the headless shell 132 MB (CDN Content-Length, 2026-11-09). Plain `chromium` fetches both, so `--only-shell` drops the 207 MB. Seconds unmeasured. **Risk** Headed runs and `channel: 'chromium'|'chrome'` cannot use the shell. `--with-deps` still runs apt, which cannot be cached.

**9. Container image instead of installing.** **Check** Compare `container: image: mcr.microsoft.com/playwright:v<X>-noble` with `npm ls @playwright/test`, and look for a `playwright install` step inside that job. **Good** The tag equals the package version exactly, and there is no install step: the image sets `PLAYWRIGHT_BROWSERS_PATH=/ms-playwright` and ships all browsers plus OS deps ([Dockerfile](https://github.com/microsoft/playwright/blob/v1.65.0/utils/docker/Dockerfile.noble)). Use `options: --user 1001` as in the CI docs.
**Fix** Switch to the image when the install and deps steps dominate. Otherwise stay on the VM.
**Gain** Skips the download and apt, but costs a pull of ~1.0 GB compressed (v1.65.0-noble amd64, `docker manifest inspect`, local) on every hosted job. Compare `Initialize containers` with the steps it replaces. **Risk** If the versions differ, Playwright "will be unable to locate browser executables" ([docker](https://playwright.dev/docs/docker)), so bump both together. The image ships Node 26 since 1.65. Without `--ipc=host`, Chromium "can run out of memory and crash".

**10. Recording traces and video for every test.** **Check** `rg -n "trace:|video:|screenshot:|--trace" playwright*.config.* package.json .github/workflows`. **Good** `trace: 'on-first-retry'` (needs `retries > 0`), video `'off'` or `'on-first-retry'`, and `screenshot: 'only-on-failure'`.
**Fix** Replace `'on'` and the record-always modes. `retain-on-failure` and `retain-on-failure-and-retries` record every run; `retain-on-first-failure` records every first run ([trace/video modes](https://playwright.dev/docs/test-use-options)). The trace object's `snapshots: { screen: true }` (1.63+) adds a screenshot per action.
**Gain** Typical, unmeasured. The docs call `trace: 'on'` "very performance heavy" ([best practices](https://playwright.dev/docs/best-practices)). **Risk** You get no trace for a failure that does not recur on retry.

**11. Retries and red runs.** **Check** `retry_s` and `flaky` from the jq above, plus `retries`, `retryStrategy` and `maxFailures` in the config. **Good** Retry time is a small share of busy time, and CI sets `maxFailures` (`-x`, `--max-failures`) so a broken build stops early. Flakes stay visible through `failOnFlakyTests` (1.52+).
**Gain** Saves time on red and flaky runs only. Each failure tears down the worker and its browser, and worker fixtures rerun in the new one ([retries](https://playwright.dev/docs/test-retries)). `retryStrategy: 'isolated'` (1.62+) runs retries one by one at the end, "at the expense of the total run time". **Risk** `maxFailures` hides any later failures in that run.

**12. Every browser project on every PR.** **Check** The number of `projects`: each browser or device multiplies the suite. **Good** PRs run one browser, and the full matrix runs on main or nightly. On 1.64+, `default: false` keeps a project selectable with `--project` without running it by default. It still runs when another project depends on it ([TestProject](https://playwright.dev/docs/api/class-testproject)).
**Gain** About (projects − 1)/projects of the PR test step (heuristic). **Risk** Guardrail 3: a documented browser commitment stays, so move the project to main or nightly instead of deleting it.

## Cache paths
- **Browsers:** `~/.cache/ms-playwright` (Linux), `~/Library/Caches/ms-playwright` (macOS), `%USERPROFILE%\AppData\Local\ms-playwright` (Windows), or `$PLAYWRIGHT_BROWSERS_PATH`. `PLAYWRIGHT_BROWSERS_PATH=0` (hermetic) puts them in `node_modules/playwright-core/.local-browsers`, which `npm ci` wipes. The variable does not move the Chrome/Edge channels. The official image uses `/ms-playwright`: nothing to cache.
- **Docs stance:** "Caching browser binaries is not recommended", because restoring takes about as long as downloading and Linux OS deps cannot be cached. If you cache anyway, key "against a hash of the Playwright version" ([CI](https://playwright.dev/docs/ci)). Measure restore against download on the runner.
- **Key:** `pw-${{ runner.os }}-${{ runner.arch }}-<version>-<browser set, e.g. chromium-shell>`, with the version from `node -p "require('@playwright/test/package.json').version"`. Never key on the lockfile hash, which any dependency bump busts. Use no `restore-keys`, because old browser builds are dead weight.
- **Order:** `npm ci`, then resolve the version, restore, run `npx playwright install <browsers>` **unconditionally**, then run `npx playwright install-deps <browsers>` **unconditionally**. On a hit the install is a no-op: (local) 0.6 s for an install that took 10.8 s when it downloaded. Skipping `install-deps` on a hit means launch failures on a fresh VM.
- **Garbage collection:** Playwright garbage-collects the browsers of older Playwright versions as you update ([browsers](https://playwright.dev/docs/browsers)). On 1.63+, `install --no-remove` keeps the browsers of other installations.
- **Test transform cache:** `$TMPDIR/playwright-transform-cache-<euid>` (`playwright-transform-cache` on Windows); 1.65+ can override it with `PLAYWRIGHT_TRANSFORM_CACHE_DIR` ([compilationCache.ts](https://github.com/microsoft/playwright/blob/v1.65.0/packages/playwright/src/transform/compilationCache.ts)). It only holds transpiled test files, so it is not worth a cache entry (heuristic).
- **Not caches:** `test-results/` (outputDir, cleared each run), `blob-report/` (cleared before writing), `playwright-report/`, and `playwright/.auth/` (expires, so regenerate it each run). The app build that `webServer` serves is cached under its bundler's stack file.

## Version traps
- 1.20 `fullyParallel` · 1.27 percentage `workers` · 1.37 blob reporter + `merge-reports` · 1.44 `--last-failed`, `PLAYWRIGHT_BLOB_OUTPUT_FILE` · 1.46 `--only-changed [ref]`.
- **1.38:** the `playwright` package stopped downloading browsers on `npm install` (`@playwright/test` never did). `@playwright/browser-chromium` and similar packages *still* download during install: a hidden install cost.
- **1.47:** the plain `:v<X>` image tag is Ubuntu 24.04 noble; use `-jammy` for 22.04. A `-resolute` (26.04) tag also exists. **1.63** dropped Ubuntu 20.04.
- **1.49:** added `--only-shell`/`--no-shell`. The `chrome`/`msedge` channels switched to new headless; Chromium opts in via `channel: 'chromium'`.
- **1.50:** `webServer.gracefulShutdown` (default `SIGKILL`). `webServer.port` is deprecated in favour of `url`.
- **1.51:** `reportSlowTests` threshold went from 15 s to 5 min, so old runbooks that expect slow-file lines see nothing.
- **1.52:** per-project `workers`, `failOnFlakyTests`. **1.57:** Chrome for Testing builds (headless = `chrome-headless-shell`), Speedboard, `webServer.wait`. **1.58:** Speedboard Timeline for merged reports.
- **1.59:** trace mode `retain-on-failure-and-retries`. **1.60:** `workers: 0` or a negative value is rejected. **1.61:** `video` accepts all trace modes. **1.62:** `retryStrategy`.
- **1.63:** test locks, `perfetto` reporter, `--add-reporter`, `install --no-remove`, HTML step waterfall; Linux arm64 now gets Chrome for Testing.
- **1.64:** `--shuffle [seed]`, `describe.configure({ lock })`, `TestProject.default`, VP9 video ("takes less CPU"). The blob reporter kept reports with other names (1.64 only).
- **1.65:** `-exclusive-` lock. A sharded run that matches no tests fails without `--pass-with-no-tests`. The blob reporter clears its output dir again: (local) two shards written to one `PLAYWRIGHT_BLOB_OUTPUT_DIR` leave only the last zip, so give each shard its own dir. Also new: the `failures` reporter and `onlyFailures`, and `PLAYWRIGHT_TRANSFORM_CACHE_DIR`. Node 20 is no longer tested, and the image moved from Node 24 to 26. `bunx --bun playwright test` runs under Bun, which skips Babel and the compilation cache.
- **Scaffold vs docs:** create-playwright (since 2026-02-12) emits `fullyParallel: true`, `retries: process.env.CI ? 2 : 0` and `trace: 'on-first-retry'`, and no longer emits CI `workers: 1`. The CI guide still shows `workers: process.env.CI ? 1 : undefined`, and older repos carry that line.
