# nx — optimize-build stack reference
Use when: detect-stack.sh reported `nx`. Lanes: install, typecheck-lint, bundle, topology, cache.

Checked 2026-11-09, re-verified 2026-11-18. Latest on 2026-11-18: `nx` 24.0.6 (24.0.0 on npm 2026-10-21), `nrwl/nx-set-shas` v5.1.0, `nx-cloud` 19.1.5. Run `npx nx report` first: most traps below depend on the major/minor version.

## Measure
- **End-of-run performance report (23.1+)**: printed after every `nx run-many`/`affected` run, in every output mode: `Run duration`, `Cache`, `Critical path: <t> (<n> tasks)`, `Recoverable time: <t> (<p>% of the run)`. "Recoverable" is slot-queued time, which more `--parallel` or more machines would win back. Recommendations appear only when they are actionable, and only on runs over 30 s. On GitHub Actions the outermost run also appends `## Nx Run Report — \`<cmd>\`` to the job summary, so read it from the run page (source: `tasks-runner/life-cycles/performance-*.js` in nx 24.0.5).
- **Per-task ms**: `NX_PERF_LOGGING=true npx nx affected -t build` prints `Task Execution Timings:` as JSON `{ "<project>:<target>": ms }` at the end, plus Nx's own perf marks. For a timeline, `NX_PROFILE=profile.json npx nx run-many -t build` writes a trace you open in Chrome DevTools → Performance ([profiling](https://nx.dev/docs/troubleshooting/performance-profiling)).
- **Nx overhead (project graph, plugin inference)**: `NX_PERF_LOGGING=true NX_DAEMON=false npx nx show projects`. The daemon is off on CI and in Docker unless `NX_DAEMON=true` (source: `daemon/client/client.js`), so every `nx` call in a CI job rebuilds the graph. 23.3 reports a case where glob matching alone took "40 seconds of a 70-second ESLint project inference" ([23.3](https://nx.dev/blog/nx-23-3-release)).
- **Cache hits in CI logs**: the task line ends in `[local cache]`, `[remote cache]` or `[existing outputs match the cache, left as is]`, and the footer reads `Nx read the output from the cache instead of running the command for X out of Y tasks.` Since 23.2, CI defaults to `static-failures-only`, which collapses successful tasks to one line. Set `NX_DEFAULT_OUTPUT_STYLE=static` (or `--output-style=static`) to get full logs ([23.2](https://nx.dev/blog/nx-23-2-release)). Since 23.3, an AI agent running Nx gets `summary` by default ([23.3](https://nx.dev/blog/nx-23-3-release)). Pass `--output-style=static` when you measure locally, or the per-task cache tags are hidden.
- **What runs and why**: `npx nx affected -t build --graph=tasks.json` writes the task graph without running anything. `npx nx graph --file=graph.json` writes the project graph. `npx nx affected -t build --explain` (23.3+, needs `-t`; `--explain=stdout` gives JSON) prints why each task is affected, then exits ([affected](https://nx.dev/docs/features/ci-features/affected)).
- **Resolved config**: `npx nx show project <p> --json` (JSON is the default outside a TTY) shows the effective `cache`/`inputs`/`outputs`/`dependsOn` after plugin inference and targetDefaults. `npx nx show target inputs <p>:<t> --check <file|ENV>` and `npx nx show target outputs <p>:<t>` list the resolved files (present in 24.0.5; check `--help` on older versions).
- With Nx Cloud connected, the run URL printed at the end shows per-task timings and cache status.

## Checks
1. **Affected selection in CI.** **Check** `grep -nE 'nx (affected|run-many)|nx-set-shas|NX_(BASE|HEAD)|fetch-depth|filter:' .github/workflows/*.y*ml`. **Good** `nrwl/nx-set-shas@v5` (it sets `NX_BASE`/`NX_HEAD` from the last successful `main` run through the GitHub API) followed by `nx affected -t lint test build`, with checkout `fetch-depth: 0` (the docs example adds `filter: tree:0`). "Without the full Git history, there is no base commit to compare against" ([affected](https://nx.dev/docs/features/ci-features/affected)). **Fix** replace `run-many --all` on PRs with `affected`. Set `main-branch-name` if the default branch is not `main`, and set `last-successful-event` if `main` CI is not triggered by `push` (the default). **Gain** the unaffected share of tasks; typical, unmeasured. **Risk** when no successful `main` run is found, nx-set-shas warns and uses `HEAD~1`, which under-selects on multi-commit PRs. Set `error-on-no-successful-workflow: true` to fail instead ([action.yml](https://github.com/nrwl/nx-set-shas/blob/main/action.yml)). Keep full `run-many` on `main`/release.
2. **Lockfile change affects everything.** **Check** `jq '.pluginsConfig["@nx/js"].projectsAffectedByDependencyUpdates' nx.json`. **Good** `"auto"`, which affects only projects whose resolved dependencies changed. The default `"all"` affects every project ([nx.json](https://nx.dev/docs/reference/nx-json)). **Gain** large on Renovate/Dependabot PRs; unmeasured. **Risk** tools invoked outside the dependency graph (root scripts) are not selected.
3. **Task-based affected (24.0+).** **Check** `jq '.affected' nx.json`. `{"legacy": true}` was set by the 24 migration and keeps whole-project selection. **Fix** remove it, then compare `nx affected -t build --explain` before and after. Set `NX_LEGACY_AFFECTED` for the whole job so `nx show projects --affected` and `nx affected` agree. **Gain** tasks whose inputs did not change are skipped; unmeasured. **Risk** "`dependsOn` alone doesn't make a task affected", so a task that reads undeclared inputs gets silently skipped. Fix inputs (check 5) first.
4. **Caching enabled per target.** **Check** `npx nx show project <p> --json | jq '.targets|map_values({cache,outputs})'` for lint/test/build/typecheck. Also run `grep -n cacheableOperations nx.json`. **Good** `cache: true` and correct `outputs` on every side-effect-free target. **Fix** `targetDefaults.<target>.cache: true`. Run `nx repair` (which re-runs every migration in the `nx` package) to convert the pre-17 `tasksRunnerOptions…cacheableOperations`: the nx 24.0.5 runtime reads only `task.cache` (source: `tasks-runner/utils.js`), so a stale `cacheableOperations` means no caching. In 24, when an executor key and a target-name key both match, `cache` is read only from the executor key ([24](https://nx.dev/blog/nx-24-release)). **Gain** the whole task on a hit; unmeasured. **Risk** never cache e2e that hits live services, or a target that is also `continuous` (rejected).
5. **Inputs too broad (misses) or too narrow (wrong hits).** **Check** `jq '{namedInputs, targetDefaults}' nx.json` and `npx nx show target inputs app:build --check apps/app/src/x.spec.ts`. Without `inputs`, Nx hashes all files of the project and its dependencies and all external deps ([inputs](https://nx.dev/docs/reference/inputs)). **Good** `"production": ["default", "!{projectRoot}/**/*.spec.*", "!{projectRoot}/jest.config.ts", …]`, build `["production","^production"]`, test `["default","^production"]`, and `sharedGlobals` listing root configs. Declare `{ "env": "X" }`, `{ "runtime": "node --version" }` and `{ "externalDependencies": ["vite"] }` where outputs depend on them. Use `"..."` to extend inherited inputs instead of replacing them ([nx.json](https://nx.dev/docs/reference/nx-json)). **Gain** test-only edits stop invalidating dependents' builds; unmeasured. **Risk** an excluded file that affects output gives stale hits, which is a correctness bug. Nx Cloud Ultracache (24+) hashes from recorded reads instead ([remote cache](https://nx.dev/docs/features/ci-features/remote-cache)).
6. **Parallelism.** **Check** `grep -nE -- '--parallel|NX_PARALLEL|"parallel"' nx.json package.json .github/workflows/*`. The default is **3** ([commands](https://nx.dev/docs/reference/nx-commands)). A trailing `%` means a share of `os.availableParallelism()`, e.g. `--parallel=100%` (source: `concurrency()` in `command-line/yargs-utils/shared-options.js`, 24.0.5). **Good** parallel ≈ runner vCPUs, sized by the report's `Recoverable time`. **Fix** `--parallel=100%` (check that your version parses `%`) or `NX_PARALLEL`. **Gain** up to `Recoverable time`; measured per run by the report. **Risk** OOM and timeouts when each task's Jest/Vitest also forks workers (see test-parallelism.md, monorepo nesting).
7. **Several `nx` calls per job.** **Check** count `nx ` invocations per job. **Good** one `nx affected -t lint typecheck test build`. **Fix** merge them. With the daemon off in CI, each call pays graph creation (measure it with `NX_PERF_LOGGING`). **Gain** graph time × (calls − 1); unmeasured. **Risk** a single step mixes logs, so rely on the job summary report.
8. **Remote cache.** **Check** `jq '{nxCloudId, nxCloudAccessToken}' nx.json`, plus `grep -nE 'NX_CLOUD_ACCESS_TOKEN|NX_SELF_HOSTED_REMOTE_CACHE|NX_NO_CLOUD|skip-nx-cache' .github/workflows/*` and `grep -E '"@nx/(s3|gcs|azure|shared-fs)-cache"' package.json`. **Good** Nx Cloud (`npx nx@latest connect` writes `nxCloudId`), a read-write `NX_CLOUD_ACCESS_TOKEN` only on protected branches and a read-only one elsewhere ("writes to a cache isolated to that run"), and the deploy artifact built with `--skip-nx-cache` ([remote cache](https://nx.dev/docs/features/ci-features/remote-cache), [cache security](https://nx.dev/docs/kb/cache-security)). Self-hosted: `NX_SELF_HOSTED_REMOTE_CACHE_SERVER` + `NX_SELF_HOSTED_REMOTE_CACHE_ACCESS_TOKEN`, against the OpenAPI spec ([self-hosted](https://nx.dev/docs/kb/self-hosted-caching)). **Fix** replace the deprecated bucket packages. **Gain** cross-run and cross-PR hits; unmeasured. **Risk** CREEP (CVE-2025-36852): the bucket packages are "deprecated as of 2026-05-21" and the flaw "cannot be patched". A custom server must return 409 for existing keys ([deprecation](https://nx.dev/docs/reference/deprecated/self-hosted-cache-packages)). This is a guardrail-1 issue, not only speed.
9. **`actions/cache` on the Nx cache.** **Check** a workflow caching `.nx/cache`, `~/.nx` or `$NX_CACHE_DIRECTORY`, and its log for `Unrecognized Cache Artifacts` or zero `[local cache]` lines after a restore hit. **Why** since Nx 20 the cache is indexed by a DB named `<machine-id>-v<N>.db` (source: `native/db/mod.rs`). Nx 21 removed the file cache, and `NX_REJECT_UNKNOWN_LOCAL_CACHE=0` is "not supported" (source: `cache.js`). Artifacts restored on a runner with a different machine ID are ignored. Whether GitHub-hosted runners share a machine ID is **untested**, so decide from the log. **Fix** use the remote cache (check 8), or delete the step to save its restore and save time. **Gain** the step's measured restore + save seconds when hits are zero. **Risk** none if the logs show no hits.
10. **Typecheck/lint inference.** **Check** `npx nx show project <p> --json | jq '.targets.typecheck'`. **Good** `@nx/js/typescript` infers `typecheck`. In a TS solution setup (project references) it runs `tsc --build --emitDeclarationOnly` and depends on the deps' typecheck. Otherwise it runs `tsc -p <tsconfig> --noEmit` with no outputs ([TS](https://nx.dev/docs/technologies/typescript/introduction)). The plugin option `compiler: "tsc"|"tsgo"` defaults to `tsc`. Put `nx sync:check` first in CI so stale references fail fast. Tasks also fail in CI when sync is stale, and `--skip-sync` skips that check ([sync](https://nx.dev/docs/concepts/sync-generators)). `--batch`/`NX_BATCH_MODE` batches executors that support it. 23.3 batches `@nx/oxlint:lint` by default ([23.3](https://nx.dev/blog/nx-23-3-release)). **Gain** per-project cached typecheck/lint instead of one repo-wide pass; unmeasured. **Risk** project references reject circular dependencies.
11. **Bundle.** **Check** `npx nx affected -t build --graph=tasks.json` for `^build` chains through libs that only feed the bundler. Then run `npx nx show target outputs app:build`. **Good** the outputs cover everything later steps read (missing outputs mean a hit restores nothing), and deploy builds skip the cache (check 8). **Gain** the skipped library builds on PRs; *typical, unmeasured*. **Risk** missing `outputs` means a cache hit restores nothing.
12. **Distribution (topology).** **Check** `ls .nx/pipelines/ci.yaml .nx/ci-config.yaml` and `grep -n 'nx-cloud start-' .github/workflows/*`. **Good** Nx Cloud Workers: `.nx/pipelines/ci.yaml` with `worker-templates.default.workers: 3 linux-large-js` and `stop-after: [build]` (the older `.nx/ci-config.yaml` with `dte.distribute-on`/`lifecycle.stop-after` is deprecated, and `start-workers` keeps reading it while it exists, so migrate it), and `npx nx-cloud start-workers` placed **before** install so workers boot in parallel ([setup CI](https://nx.dev/docs/getting-started/setup-ci)). Slow e2e can be split per file with plugin option `ciTargetName: "e2e-ci"`, giving `e2e-ci--<file>` tasks ([Atomizer](https://nx.dev/docs/features/ci-features/split-e2e-tasks)). On 24, `@nx-depends-on` in a spec narrows its hash without Ultracache ([24](https://nx.dev/blog/nx-24-release)). **Gain** vendor benchmarks only: wall-clock 48 → 12 min ([23](https://nx.dev/blog/nx-23-release)), and dynamic task packing "cut their VM minutes by 35 to 50%" ([24](https://nx.dev/blog/nx-24-release)). **Risk** cost and vendor lock-in, and it needs secrets that forked PRs lack (guardrail 2).

## Cache paths
| Nx version | Task cache (artifacts) | Index / workspace data |
|---|---|---|
| <17 | `node_modules/.cache/nx` | — |
| 17.0–23.1 | `<ws>/.nx/cache` (17.0.0 migration) | `<ws>/.nx/workspace-data` (19.2+); cache DB lives here from 20 |
| ≥23.2 (2026-09-02) | `~/.nx/<id>/cache`, shared by every checkout, worktree and clone | DB in `~/.nx/<id>/databases/<machine-id>-v<N>.db`; daemon logs stay in `<ws>/.nx/workspace-data` |
- `<id>` = first 16 hex of sha256(`nxCloudId`, else an id from the git remote or first commit) (source: `utils/cache-directory.js`). Nx skips `~/.nx` and uses the configured directories (defaults `<ws>/.nx/cache` + `<ws>/.nx/workspace-data`; from 24.0.6 a configured directory outside the workspace that other users can write to is an error unless `NX_ALLOW_INSECURE_DIRECTORIES=true`) when `cacheDirectory` is set in nx.json, when `NX_CACHE_DIRECTORY`, `NX_WORKSPACE_DATA_DIRECTORY` or `NX_PROJECT_GRAPH_CACHE_DIRECTORY` is set, when there is no identity (not git, or a shallow clone with no remote), or when `~/.nx` is not writable. The docs say "Point your CI cache step at `~/.nx` instead, or set `NX_CACHE_DIRECTORY`" ([kb](https://nx.dev/docs/kb/change-cache-location)). Check 9 explains why that rarely hits.
- Eviction: `maxCacheSize` (or `NX_MAX_CACHE_SIZE`) defaults to 10 % of the disk, capped at 10 GB. Nx removes LRU entries until the cache is below 90 % of the limit, `0` means no limit, and entries unread for 7 days are always removed ([nx.json](https://nx.dev/docs/reference/nx-json)).
- If an `actions/cache` step is kept: key `nx-${{ runner.os }}-<nx version>-${{ hashFiles('<lockfile>') }}-${{ github.sha }}` with prefix restore, saved only on `main`. Restore before the first `nx` call. The order relative to install does not matter, because the path is outside `node_modules` (unless `cacheDirectory` points inside it). Cache the DB directory together with the artifacts.
- Remote: Nx Cloud is checked after the local cache misses. `--skip-nx-cache` (`NX_SKIP_NX_CACHE`) skips local and remote, while `--no-cloud`/`NX_NO_CLOUD`/`--skipRemoteCache`/`NX_SKIP_REMOTE_CACHE` skip only the remote ([skipping](https://nx.dev/docs/kb/skipping-cache), [env](https://nx.dev/docs/reference/environment-variables)). `nx reset --onlyCache` clears the local cache.

## Version traps
- **17.0**: cache moved to `.nx/cache`, and the migration turned `cacheableOperations` into `targetDefaults.<t>.cache: true`. 24.0.5 does not read `cacheableOperations` at runtime (check 4).
- **18.1**: `affected.defaultBase` → top-level `defaultBase` (default `main`). The old key is deprecated.
- **19.2**: workspace data moved to `.nx/workspace-data`. `NX_PROJECT_GRAPH_CACHE_DIRECTORY` is now a deprecated alias of `NX_WORKSPACE_DATA_DIRECTORY`.
- **20.0**: DB cache became the default. The 20.0.1 migration set `useLegacyCache: true` on upgraded workspaces, and `tasksRunnerOptions` was deprecated ([legacy cache](https://nx.dev/deprecated/legacy-cache)).
- **21.0**: removed the legacy file cache, `useLegacyCache` and custom tasks runners. `NX_REJECT_UNKNOWN_LOCAL_CACHE=0` only warns. CI setups that shared the cache folder lost their hits.
- **Security pins**: nx 20.9.0, 20.10.0, 20.11.0, 20.12.0, 21.5.0, 21.6.0, 21.7.0 and 21.8.0 were malicious publishes (GHSA-cxm3-wv7p-598c), so grep the lockfile. The self-hosted remote cache has a Zip-Slip in nx 20.8.0–22.7.6 and 23.0.0–23.0.1, fixed in 22.7.7 / 23.0.2 (GHSA-vp3h-ghgh-jr7g). The `@nx/*-cache` bucket packages are deprecated as of 2026-05-21, unpatched.
- **23.0** (2026-06-16): Node ≥22. Per-tool executors (`@nx/jest:jest`, `@nx/eslint:lint`, `@nx/cypress:cypress`, `@nx/playwright:playwright`, …) are deprecated in favour of inferred tasks (`nx g convert-to-inferred`). Vitest moved to `@nx/vitest`.
- **23.1**: added the performance report and filtered (nested-array) `targetDefaults`.
- **23.2** (2026-09-02): cache and DB moved to `~/.nx/<id>`, so CI cache steps on `.nx/cache` silently cache nothing. The CI output style became `static-failures-only`. A migration sets `cache` on executor-keyed targetDefaults. Added `.nx/ci-config.yaml` for distribution (now deprecated in favour of `.nx/pipelines/ci.yaml`, which the `ci-workflow` generator writes since 24.0.6), and the experimental `@nx/oxlint` (needs Oxlint ≥1.70.0).
- **23.3** (2026-10-07): task-based affected is opt-in via `NX_LEGACY_AFFECTED=false`. Added `--explain`, the `summary` output style (automatic for AI agents) and `includeIgnored: true` on fileset inputs.
- **24.0** (2026-10-21): task-based affected became the default, and the migration writes `affected.legacy: true`. `cache` is now read from the executor key only, and the target-name fallback is gone. 35 executors were removed, along with `withNx`, `composePlugins`, `nxViteTsPaths` and Module Federation. Custom hashers are deprecated (removed in 25). Nx Agents are now "Workers", and the old names warn. Ultracache is on by default in CI when it is enabled in Nx Cloud, and `NX_CLOUD_ULTRACACHE_MODE=off` opts one pipeline out (`NX_CLOUD_USE_ULTRACACHE=false` still works but is documented as legacy). Its options `ignoredReads`/`ignoredWrites` are renamed `ignoreReads`/`ignoreWrites`.
- **nx-set-shas v5** (2026-03-20): the action runs on node24. v4 pins run on the older runtime.
