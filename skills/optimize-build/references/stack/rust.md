# rust — optimize-build stack reference
Use when: detect-stack.sh reported `rust`. Lanes: install, build, typecheck-lint, test, cache.

Checked 2026-11-18. Latest that day: Rust **1.100.0** (2026-11-12), `Swatinem/rust-cache` **v2.9.3**, sccache **0.19.0**, cargo-nextest **0.9.152**, `taiki-e/install-action` **v2.90.5**, samply **0.13.1**, flamegraph **0.6.15**. **(cited)** means linked vendor text; vendor benchmarks are not independent. **(heuristic)** means typical but unmeasured, so measure it on the repo. No Rust toolchain was available for local runs, so nothing here is marked local.

## Measure
- **Which commands run:**
  ```bash
  grep -nE 'cargo (build|check|clippy|test|nextest|doc|install|fmt|chef)|rust-cache|sccache|RUSTC_WRAPPER|RUSTFLAGS|CARGO_(INCREMENTAL|PROFILE|TARGET_DIR)|--release|--all-features|--workspace|-p ' .github/workflows/*.y*ml Makefile* justfile 2>/dev/null
  cat rust-toolchain.toml rust-toolchain .cargo/config.toml 2>/dev/null; grep -nE '^\[profile|lto|codegen-units|debug|incremental|opt-level' Cargo.toml
  ```
- **Where compile time goes:** `cargo build --timings` writes `target/cargo-timings/cargo-timing.html`: a unit graph with the critical path, codegen time per unit, build scripts in orange, and a concurrency graph ([timings](https://doc.rust-lang.org/cargo/reference/timings.html)). Upload it as an artifact from one CI run.
- **Compile vs run:** `cargo test --no-run` builds and links every test binary without running it. The rest of the test step is run time.
- **What was rebuilt:** count `Compiling` lines per step in the CI log. On a warm dependency cache only workspace crates should appear. A registry crate that shows up in two steps of one job points to check 4.
- **Cache evidence:** rust-cache "prints detailed information about which information it considers for its cache key" ([README](https://github.com/Swatinem/rust-cache)). For sccache, run `sccache --show-stats` after the build.
- **Slow tests:** `cargo nextest run` prints a duration per test and marks slow ones. For JUnit set `[profile.ci.junit] path = "junit.xml"` in `.config/nextest.toml` ([JUnit](https://nexte.st/docs/machine-readable/junit/)).

## Checks
1. **No dependency cache.** **Check**: no `Swatinem/rust-cache` and no `actions/cache` on `target`. **Facts** ([README](https://github.com/Swatinem/rust-cache)): the action caches `~/.cargo` (registry, git dependencies, installed binaries) and the dependency artifacts in `./target`. Workspace crates are not cached. The key holds the job id, the rustc version, a hash of `Cargo.lock`, every `Cargo.toml`, `rust-toolchain*` and `.cargo/config.toml`, and env vars with the prefixes `CARGO CC CFLAGS CXX CMAKE RUST`. It "will try to restore from a previous `Cargo.lock` version". **Fix**: install the toolchain first (the key reads the rustc version), then `Swatinem/rust-cache@v2` with `save-if: ${{ github.ref == 'refs/heads/main' }}`. Jobs that build the same profile and features can share one entry with `shared-key`. **Gain**: the dependency compile, i.e. the `Compiling` lines for non-workspace crates (heuristic). The action says it is "more effective if the dependency / own code ratio is higher". **Risk**: `target` archives are large and each job id gets its own entry, so watch the 10 GB quota (`ci-github-caching.md` §1.5). An unpinned nightly discards the cache daily.
2. **Cache hit, dependencies still recompile.** **Check**: an exact hit in the log, then `Compiling <registry crate>`. Causes: `RUSTFLAGS`, features or profile differ from the job that saved; the toolchain floated; a step runs `cargo clean`. **Fix**: pin the toolchain in `rust-toolchain.toml`, and use one feature set and profile per cache (check 4). **Gain**: the full dependency build on every run (heuristic). **Risk**: none.
3. **Incremental compilation in CI.** **Facts**: the dev profile has `incremental = true` ([profiles](https://doc.rust-lang.org/cargo/reference/profiles.html)). rust-cache sets `CARGO_INCREMENTAL=0` and strips incremental artifacts before saving, and sccache cannot cache incrementally compiled crates ([sccache](https://github.com/mozilla/sccache#known-caveats)). **Check**: neither rust-cache nor `CARGO_INCREMENTAL=0` in the job. **Fix**: `CARGO_INCREMENTAL=0` in the workflow `env`. **Gain**: less disk I/O and a smaller `target` (heuristic, small). **Risk**: none on fresh runners.
4. **Steps that cannot share artifacts.** **Check**: one job runs steps with different shapes, and the same dependency compiles in more than one step:
   - `cargo check`/`clippy` then `cargo build`/`test`: check artifacts are metadata only, so the build compiles every dependency again with codegen.
   - A dev-profile step and a `--release` step.
   - `--all-features` in one step and default features in another, or `-p <crate>` versus `--workspace` (feature unification differs).

   **Fix**: one profile and one feature set per job. Move clippy to a parallel job with its own cache when wall-clock matters. **Gain**: one dependency build per mismatch removed (heuristic). **Risk**: unifying on `--all-features` hides feature-combination bugs, so keep a feature matrix on the default branch.
5. **Full debug info.** **Fact**: dev and test profiles default to `debug = true`, full debug info ([profiles](https://doc.rust-lang.org/cargo/reference/profiles.html)). **Fix**: in CI `env`, `CARGO_PROFILE_DEV_DEBUG=line-tables-only` (panics keep file and line) or `0`. **Gain**: less codegen and link work and a smaller cache. The Cargo docs give no number, so measure with `--timings` (heuristic). **Risk**: no variable inspection in a debugger attached to CI artifacts.
6. **Linker.** **Fact**: `rust-lld` is the default linker on `x86_64-unknown-linux-gnu` since 1.90.0 (2025-09-18). On ripgrep debug builds, linking was about 7× faster on incremental rebuilds and a from-scratch build about 20% faster (cited, [Rust blog](https://blog.rust-lang.org/2025/09/01/rust-lld-on-1.90.0-stable/)). **Check**: a toolchain pinned below 1.90, another target (arm64 Linux, macOS, Windows), or `-Clinker-features=-lld` in `RUSTFLAGS`. **Fix**: raise the pin. On other targets set a faster linker in `.cargo/config.toml` and measure (heuristic). **Risk**: linker-specific failures; the blog documents the opt-out.
7. **One test binary per file in `tests/`.** **Fact**: each file there is a separate crate, linked into its own executable ([cargo targets](https://doc.rust-lang.org/cargo/reference/cargo-targets.html#integration-tests)). **Check**: `ls tests/*.rs | wc -l` per crate against the `cargo test --no-run` time. **Fix**: one `tests/it/main.rs` that declares the former files as modules. **Gain**: one link instead of N (heuristic). **Risk**: under `cargo test`, tests now share one process, so statics and env mutations can collide.
8. **Test runner.** **Facts**: nextest runs every test in its own process and in parallel across binaries. "Doctests are currently not supported because of limitations in stable Rust" ([nextest](https://nexte.st/)). **Check**: plain `cargo test` across many binaries. **Fix**: `cargo nextest run`, plus `cargo test --doc` as a separate step. **Gain**: vendor claim of "Up to 3× faster than `cargo test`" (cited); measure it. **Risk**: tests that relied on shared in-process state or on order now fail, and forgetting the doctest step silently drops them.
9. **Shards that each compile.** **Check**: a test matrix where every leg runs `cargo build`/`cargo test`. **Fix**: build once with `cargo nextest archive --archive-file t.tar.zst`, pass it as an artifact, and run `cargo nextest run --archive-file t.tar.zst --partition slice:${i}/${n}` per shard. Shards need the source at the same revision and nextest, but "Cargo does not need to be installed on the target machine" ([archiving](https://nexte.st/docs/ci-features/archiving/)). `slice:` (≥0.9.127) is the recommended kind; `count:` is deprecated ([partitioning](https://nexte.st/docs/ci-features/partitioning/)). **Gain**: shards skip the toolchain, cache restore and compile. When sharding pays at all: `test-parallelism.md` §7. **Risk**: the archive upload and download time; a different checkout path needs `--workspace-remap`.
10. **Tools built with `cargo install`.** **Check**: `cargo install <tool>` steps (nextest, cargo-deny, sqlx-cli, wasm-pack). They compile from source. **Fix**: `taiki-e/install-action` downloads checksummed prebuilt binaries. Its default fallback is cargo-binstall, which can still build from source; `fallback: none` makes that an error ([README](https://github.com/taiki-e/install-action)). Install the toolchain with `--profile minimal` plus only the components the job uses. **Gain**: the tool compile, often minutes (heuristic). **Risk**: none.
11. **sccache: when, and its limits.** **Facts** ([README](https://github.com/mozilla/sccache#known-caveats)): `bin`, `dylib`, `cdylib` and `proc-macro` crates cannot be cached, incremental crates cannot be cached, and absolute paths must match unless `SCCACHE_BASEDIRS` is set. Enable with `mozilla-actions/sccache-action` plus `SCCACHE_GHA_ENABLED=true` and `RUSTC_WRAPPER=sccache` ([action](https://github.com/Mozilla-Actions/sccache-action)). **Use it** when many jobs or branches compile overlapping crates under different lockfiles, or on self-hosted runners with a shared store. **Skip it** when rust-cache already hits: both then store the same dependencies (heuristic). **Check** the hit rate with `sccache --show-stats`. **Risk**: with the GHA backend every unit is a cache entry, which eats quota and can hit the upload rate limit.
12. **Release settings on PR jobs.** **Check**: `--release` on PR test jobs with `lto` or `codegen-units = 1` in `[profile.release]`. **Fix**: test on the dev profile in PRs, or add a `[profile.ci]` that inherits `release` with `lto = false` and the default `codegen-units`. Build the real release profile on the default branch and tags. **Gain**: read it from `--timings` (heuristic). **Risk**: slow tests at `opt-level = 0`; `[profile.dev.package."*"] opt-level = 2` optimises dependencies only, and that build is cached.
13. **Docker.** **Check**: `COPY . .` before `cargo build` in a Dockerfile. Every source change rebuilds all dependencies. **Fix**: cargo-chef: `cargo chef prepare --recipe-path recipe.json` in a planner stage, `cargo chef cook --release --recipe-path recipe.json` as its own layer, then the build ([cargo-chef](https://github.com/LukeMathWalker/cargo-chef)). The layer cache must be exported for this to help on hosted runners ([docker.md](docker.md) check 4). **Gain**: the dependency build on source-only changes (heuristic). **Risk**: the cook and build flags must match exactly.

## Profile one slow test
Use this when a test's own run time dominates: not the compile (`cargo test --no-run`) and not the link (checks 6–7). Work in a scratch copy and write every output outside the repo. Nothing here was run locally; the commands come from the linked docs.
1. **Find it.** nextest prints a duration per test and a `SLOW [> 60.000s]` line once a test passes the slow threshold, 60 seconds by default. In `.config/nextest.toml`, `slow-timeout = { period = "30s", terminate-after = 4 }` lowers the threshold and ends the test as `TIMEOUT` after four periods ([slow tests](https://nexte.st/docs/features/slow-tests/)).
2. **Isolate it.** `cargo test --no-run` prints the path of each test executable. Run one directly: `target/debug/deps/<crate>-<hash> --exact module::test_name --test-threads=1 --nocapture`.
3. **Profile the binary.** `samply record target/debug/deps/<crate>-<hash> --exact module::test_name` (samply 0.13.1). "On macOS and Windows, both on- and off-cpu samples are collected (so you can see under which stack you were blocking on a lock, for example). On Linux, only on-cpu samples are collected". Linux also needs perf events enabled for unprivileged users ([samply](https://github.com/mstange/samply)).
4. **Or a flame graph.** `cargo flamegraph --dev --unit-test <crate> -- module::test_name`, or `--test <integration test> -- test_name` (flamegraph 0.6.15). Without the trailing filter it "profiles the test harness and all tests in the binary". `--dev` matches the profile the tests run under; the default is release. On Linux with lld, the default linker since 1.90, perf needs `rustflags = ["-Clink-arg=-Wl,--no-rosegment"]` for accurate stacks ([flamegraph](https://github.com/flamegraph-rs/flamegraph)).
5. **Keep symbols.** A profiling build needs at least `debug = "line-tables-only"`. Unset a CI-wide `CARGO_PROFILE_DEV_DEBUG=0` (check 5) for this run (heuristic).
6. **Computing or waiting?** On Linux both profilers show on-CPU time only. If the samples add up to far less than the test's wall time, the test waits (sleep, I/O, locks, an async runtime idling), so read the test for sleeps and timeouts, or profile on macOS where samply also records off-CPU stacks.

Report the top frames and their share of the test's time. That output is the evidence for the finding.

## Cache paths
| Cache | Path | Key inputs | Notes |
|---|---|---|---|
| Registry and git deps | `~/.cargo/registry/index`, `~/.cargo/registry/cache`, `~/.cargo/git/db` | `Cargo.lock` hash | Skip `~/.cargo/registry/src`: Cargo re-extracts it faster than a restore (cited, rust-cache) |
| Dependency artifacts | `./target` (per workspace) | rustc version and host, `Cargo.lock` and `Cargo.toml` hashes, `RUSTFLAGS`, profile, features | rust-cache removes workspace crates, incremental data and artifacts older than a week before saving |
| sccache | GHA cache, S3, GCS, Redis | hash of each compiler invocation | Not for `bin`/`proc-macro` crates |
| nextest archive | workflow artifact | commit SHA | Passed between jobs of one run; not a cache |

## Version traps
- **Rust 1.90.0**: `rust-lld` by default on `x86_64-unknown-linux-gnu` only. Check other targets before assuming it.
- **nextest 0.9.127**: added `--partition slice:`. Older pins only have `hash:` and the deprecated `count:`.
- **rust-cache and nightly**: the key includes the rustc hash, so `toolchain: nightly` without a date misses every day.
- **sccache-action**: "Versions prior to sccache v0.11.0 probably will not work" with the current action ([action](https://github.com/Mozilla-Actions/sccache-action)).
