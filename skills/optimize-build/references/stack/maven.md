# maven — optimize-build stack reference
Use when: detect-stack.sh reported `maven`. Lanes: install, build, typecheck-lint, test, topology, cache. Test runtime cost (Spring contexts, Testcontainers, forks) is in [jvm.md](jvm.md).

Checked 2026-11-18. Latest that day: Maven **3.10.1** (2026-11-15); **4.0.0 is still a release candidate** (rc-7, 2026-09-24). maven-build-cache-extension **1.3.0**, mvnd **1.0.6** (embeds Maven 3.9.x; 2.x is a preview for Maven 4), Surefire **3.6.1**, `actions/setup-java` **v6.3.0**. **(cited)** means linked vendor text read that day. **(heuristic)** means typical but unmeasured, so measure it on the repo. No JDK was available for local runs, so nothing here is marked local.

## Measure
- **Which invocations run:**
  ```bash
  grep -nE '(mvnw?|mvnd) |setup-java|cache:|-T ?[0-9]|-o\b|-U\b|-ntp|-DskipTests|maven\.test\.skip|-pl |-am\b|clean|install|deploy|sonar' .github/workflows/*.y*ml
  ls .mvn/extensions.xml .mvn/maven.config .mvn/jvm.config 2>/dev/null; grep -c '<module>' pom.xml
  grep -rnE '<(forkCount|reuseForks|parallel|threadCount|skipTests|argLine)>' --include=pom.xml . | head -20
  ```
- **Per module:** every multi-module build ends with a `Reactor Summary` listing each module's duration. Rank it straight from the CI log.
- **Per plugin goal:** each goal prints a `--- <plugin>:<version>:<goal> (<id>) @ <module> ---` header. The Actions log timestamps every line, so the gap between two headers is that goal's time. Rank them with `loggaps.py` from `ci-github-timings.md` §6, or filter first: `grep -E ' --- .* @ .* ---' job.log`.
- **Downloads:** count `Downloaded from` lines in a run *without* `-ntp`. A warm repository cache has none.
- **Tests:** `target/surefire-reports/TEST-*.xml` and `target/failsafe-reports/`, ranked with the JUnit script in `ci-github-timings.md` §6.

## Checks
1. **The lifecycle runs more than once per job.** **Check**: several Maven steps, e.g. `mvn clean install`, then `mvn test`, then `mvn verify` or `mvn sonar:sonar`. Maven re-runs every phase up to the requested one on each invocation, so sources compile and tests run again. **Fix**: one invocation with all goals (`mvn -B verify sonar:sonar`). Prefer `verify` to `install` unless a later step reads the artifacts from `~/.m2`. **Gain**: one compile and test pass per removed invocation, read from the Reactor Summary (heuristic). **Risk**: goals that expected installed artifacts need them passed another way.
2. **Serial reactor.** **Fact**: `-T` sets the "Thread count, for instance 4 (int) or 2C/2.5C (int/float) where C is core multiplied" ([CLI](https://maven.apache.org/ref/3.9.16/maven-embedder/cli.html)). **Check**: a multi-module build with no `-T` in the command or `.mvn/maven.config`. **Fix**: `-T 1C`. **Gain**: bounded by the width of the module graph and the cores. On 2 vCPU it is small (heuristic). **Risk**: Maven warns about plugins not marked thread-safe, and tests in different modules now overlap on ports, files and databases.
3. **Dependencies download every run.** **Check**: no `cache: maven` on setup-java and no `actions/cache` on `~/.m2/repository`; `-U` in the PR command. **Facts**: setup-java caches `~/.m2/repository` keyed on a hash of `**/pom.xml`, the wrapper properties and `.mvn/extensions.xml`, and sets **no restore keys** "to start with a clear cache after dependency update" ([cache.ts](https://github.com/actions/setup-java/blob/main/src/cache.ts)). So any `pom.xml` edit, including a version bump of the project itself, is a cold download. `-U` "Forces a check for missing releases and updated snapshots on remote repositories" (CLI reference). **Fix**: `cache: maven`; for repos whose poms change on most PRs, a manual `actions/cache/restore` with a prefix `restore-keys` saved from the default branch (fix A in `ci-github-caching.md`). Drop `-U` from PR builds. **Gain**: the download time, which the `Downloaded from` count sizes (heuristic). **Risk**: prefix restores grow the repository; `mvn install` also writes the project's own artifacts there, so prune them before saving.
4. **Unchanged modules rebuild.** **Check**: a multi-module repo with no `.mvn/extensions.xml` entry for the build cache. **Facts** ([extension docs](https://maven.apache.org/extensions/maven-build-cache-extension/)): maven-build-cache-extension "calculates out-of-date modules in the build dependencies graph" and skips the rest. It needs Maven 3.9+, is declared in `.mvn/extensions.xml`, keeps its local cache in a `build-cache` directory beside the local repository, supports a remote cache, and is switched off with `-Dmaven.build.cache.enabled=false`. Its own docs say tuning "could significantly reduce … build execution time, but that is not guaranteed". **Fix**: add the extension, validate that restored builds equal clean builds, then persist `~/.m2/build-cache` or configure the remote cache. **Gain**: unchanged modules restore instead of compiling and testing (heuristic). **Risk**: an incomplete input configuration restores stale artifacts. Disable it for release builds. Maven 4 support was still "incoming" on the check date.
5. **Building everything for a one-module change.** **Fact**: `-pl` selects projects, `-am` also builds "projects required by the list", and `-amd` also builds "projects that depend on projects on the list" (CLI reference). **Check**: PR builds always run the full reactor. **Fix**: derive the changed modules from the diff and run `-pl <changed> -amd -am`; [gitflow-incremental-builder](https://github.com/gitflow-incremental-builder/gitflow-incremental-builder) automates that. Keep the full reactor on the default branch. **Gain**: the Reactor Summary time of the skipped modules (heuristic). **Risk**: a change in shared build config (parent pom, BOM) must still trigger everything.
6. **Release-only plugins on every PR.** **Check** the goal headers for javadoc, source jars, GPG signing, shading or fat jars, container image builds, licence and dependency-vulnerability scans. **Fix**: bind them in a `release` profile or a default-branch job. **Gain**: their measured goal time. **Risk**: this moves a check, so say where it now runs. Security and licence scans that are required checks stay required (guardrail 1).
7. **Test forks.** `forkCount` defaults to 1, and `reuseForks=false` starts a JVM per test class. Settings and their Surefire 3.6 changes: `test-parallelism.md` §8. Cost of losing the JVM between classes: [jvm.md](jvm.md) check 2.
8. **`-DskipTests` in a build job that only packages.** `-DskipTests` still compiles the tests; `-Dmaven.test.skip=true` skips compiling them too ([Surefire](https://maven.apache.org/surefire/maven-surefire-plugin/examples/skipping-tests.html)). **Check**: a packaging or image job that runs after a separate test job. **Fix**: `-Dmaven.test.skip=true` there, or pass the built artifact from the test job. **Gain**: the test-compile time (heuristic). **Risk**: modules that publish a test-jar need the test classes.
9. **mvnd.** **Facts** ([mvnd](https://github.com/apache/maven-mvnd)): builds run in "a long living background process", JIT-compiled code is kept between builds, and it builds modules in parallel by default. **Use it** on self-hosted or long-lived agents, or when a job must invoke Maven several times. On a fresh hosted runner with one invocation the daemon starts cold, so expect the parallelism gain only (heuristic). **Risk**: 1.x embeds Maven 3.9.x, so plugins or extensions needing 3.10 or 4 behave differently.
10. **Docker.** **Check**: `COPY . .` before `mvn package`. **Fix**: copy the poms first, resolve dependencies in their own layer (`mvn -B dependency:go-offline` with a cache mount on `/root/.m2`), then copy the source. Multi-module builds need every module's `pom.xml` in that first step. **Gain**: a source-only change skips the downloads (heuristic). **Risk**: `go-offline` does not fetch everything plugins resolve at run time, and cache mounts start empty on hosted runners ([docker.md](docker.md) check 3).

## Cache paths
| Cache | Path | Key inputs | Notes |
|---|---|---|---|
| Local repository | `~/.m2/repository` | OS, arch, hash of `**/pom.xml` + `.mvn/extensions.xml` | A download cache: prefix restores are safe. Remove the project's own installed artifacts before saving |
| Wrapper distribution | `~/.m2/wrapper/dists` | `maven-wrapper.properties` hash | Cached separately by setup-java v6 |
| Build cache extension | `~/.m2/build-cache` | computed per module from sources, dependencies and plugin config | Or a remote cache; never restore it into release builds |

## Version traps
- **Maven 4**: still a release candidate on the check date. The build cache extension and mvnd 1.x target Maven 3.9/3.10.
- **Surefire 3.6**: every test runs on the JUnit Platform and several parallel settings are ignored (`test-parallelism.md` §8).
- **setup-java v6**: keys include `.mvn/extensions.xml`; `cache-read-only: true` restores without saving; the JDK download is cached whenever `cache` is set ([README](https://github.com/actions/setup-java)).
- **`-ntp`** hides the download lines you need for check 3. Measure once without it.
