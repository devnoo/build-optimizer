# turbo — optimize-build stack reference
Use when: detect-stack.sh reported `turbo`. Lanes: install, typecheck-lint, bundle, topology, cache.

Checked 2026-11-09 against turbo **2.11.10** (latest, 2026-10-20; no 3.0 release yet). **(probed)** = run locally on 2.11.10 in a scratch npm-workspaces repo. Check the repo's version first: `npx turbo --version`, `jq -r '.devDependencies.turbo // .dependencies.turbo' package.json`.
Config may be `turbo.json` or `turbo.jsonc` (2.5+). Package-level `turbo.json` files can `extends: ["//"]`, so grep all of them.

## Measure
- **Per-task timings + cache status**: `turbo run <tasks> --summarize` (or `TURBO_RUN_SUMMARY=true`) writes `.turbo/runs/<id>.json` and prints its path. In CI, upload it with `actions/upload-artifact`. Fields (probed): `.execution.{startTime,endTime,attempted,cached,success,failed}` and `.tasks[].{taskId,hash,cache.status (HIT|MISS),cache.source (LOCAL|REMOTE),cache.timeSaved (ms the original run took),execution.startTime/endTime,inputs,environmentVariables,logFile}`.
  ```bash
  F=$(ls -t .turbo/runs/*.json | head -1)
  jq -r '.tasks[] | [((.execution.endTime-.execution.startTime)/1000), .cache.status, (.cache.source//"-"), .taskId] | @tsv' $F | sort -rn | head -20
  jq '.execution | {wall_s: ((.endTime-.startTime)/1000), attempted, cached}' $F
  jq '[.tasks[] | select(.cache.status=="HIT") | .cache.timeSaved] | add/1000' $F   # seconds the cache saved this run
  ```
- **Why did it miss?** Diff two summaries (same task, two runs/branches). This is the documented method: "Comparing two summaries will show why two task's hashes are different" ([caching](https://turborepo.dev/docs/crafting-your-repository/caching)). Probed recipe:
  ```bash
  k(){ jq -S '{global: .globalCacheInputs, tasks: [.tasks[] | {taskId, hash, inputs, hashOfExternalDependencies, env: .environmentVariables, cliArguments, task: .resolvedTaskDefinition}]}' "$1"; }
  diff <(k A.json) <(k B.json)   # env shows NAME=<sha256 of value>; globalCacheInputs changing = every task misses
  ```
  Global hash inputs: resolved `turbo.json`, root-affecting lockfile changes, root internal packages, `globalDependencies` files, `globalEnv` values, flags such as `--cache-dir`/`--env-mode`/`--framework-inference`, and passthrough args. Task hash: the package's files (`inputs`), `package.json`, its lockfile slice, env, and dependency hashes ([caching](https://turborepo.dev/docs/crafting-your-repository/caching)).
- **Predict without running**: `turbo run build --affected --dry=json | jq -c '.tasks[] | {taskId, hash, s: .cache.status}'`. It reports predicted HIT/MISS (probed) and the full task list including `dependsOn` tasks. Tasks with `jit`/`dependencyOutputs` inputs report `hash: null` ([config](https://turborepo.dev/docs/reference/configuration)).
- **CI log greps** (probed): `grep -E 'cache (hit, replaying logs|miss, executing)|Cached: |FULL TURBO|Remote caching (enabled|disabled)'`. With `GITHUB_ACTIONS` set, `--log-order` `auto` → `grouped`, and each task becomes a `::group::pkg:task` block. Blocks carry **no durations**, so take durations from the summary.
- **turbo's own overhead** (startup, hashing, cache I/O): `--profile[=name]` writes a Chrome trace plus a `.md` summary (2.9+). It does not time tasks. Use it when "Time to First Task" is seconds in large repos.
- **Affected scope**: `turbo query affected --packages` gives a per-package `reason` (`FileChanged`, `DependencyChanged`, …). `--tasks build` respects `inputs` ([constructing CI](https://turborepo.dev/docs/crafting-your-repository/constructing-ci)).

## Checks
1. **No shared cache in CI** (cache lane). **Check** `grep -rnE 'TURBO_(TOKEN|TEAM|API|CACHE)|setup-turborepo-remote-cache-action|caching-for-turbo|path: .*\.turbo' .github/workflows`, plus the log line `Remote caching disabled`. **Good** remote cache (Vercel, free on all plans ([remote caching](https://turborepo.dev/docs/core-concepts/remote-caching)), or self-hosted via the OpenAPI spec with `TURBO_API`/`--api`), or at least `actions/cache` on `.turbo`. **Fix** OIDC: `permissions: {id-token: write, contents: read}` + `vercel/setup-turborepo-remote-cache-action@v1.1.0` (2026-08-21; there is no moving `v1` tag, and the guide pins `@v1.0.0`) with `team: ${{ vars.TURBO_TEAM }}` before any turbo step. Or PAT: `TURBO_TOKEN` as a secret and `TURBO_TEAM` as a var ([GHA guide](https://turborepo.dev/docs/guides/ci-vendors/github-actions)). Community, GH-cache-backed: `rharkor/caching-for-turbo` runs a local server on `:41230` and sets `TURBO_API/TOKEN/TEAM` ([README](https://github.com/rharkor/caching-for-turbo)). **Gain** sum of `timeSaved` on HIT tasks; *typical, unmeasured* until you measure it. **Risk** cache poisoning from PR writes (check 9). Fork PRs get no secrets, so they run without the remote cache.
2. **Hit restores nothing / downstream rebuilds** (correctness + waste). **Check** `jq '.tasks // .pipeline | map_values({outputs, inputs, env, cache})' turbo.json` (jq fails on JSONC comments). Look for the CI warning `no output files found for task <id>. Please check your \`outputs\` key` (probed). **Good** every file-producing task declares `outputs`. "Omitting this key or passing an empty array tells `turbo` to cache nothing" ([config](https://turborepo.dev/docs/reference/configuration)). Next.js: `[".next/**", "!.next/cache/**", "!.next/dev/**"]` ([GHA guide](https://turborepo.dev/docs/guides/ci-vendors/github-actions)). **Fix** add outputs, and exclude tool caches from them, because they bloat artifacts and upload time. **Gain** the full rebuild of later steps; *typical, unmeasured*. **Risk** none.
3. **Volatile values in the hash → misses every commit.** **Check** in the summary diff, `env`/`globalCacheInputs` change while code did not. Grep `globalEnv`/`env` and CI `env:` for `GITHUB_SHA`, `github.sha`, `run_id`, `BUILD_ID` or dates, including framework-inferred prefixes (`NEXT_PUBLIC_*`, `VITE_*`, `PUBLIC_*`, `EXPO_PUBLIC_*`, …) set from the SHA ([env vars](https://turborepo.dev/docs/crafting-your-repository/using-environment-variables)). **Good** only build-affecting vars in `env`. Runtime-only vars go in `passThroughEnv`/`globalPassThroughEnv`, which are available but not hashed. **Fix** move them, add a negation (`"!NEXT_PUBLIC_COMMIT_SHA"`), or inject the value post-build. **Gain** the hit rate on unchanged packages; *typical, unmeasured*. **Risk** if the value really is baked into the bundle, excluding it serves a stale artifact.
4. **Missing env/files → wrong hits** (correctness, report even if no speed gain). **Check** `envMode: "loose"`/`--env-mode=loose`, and gitignored `.env*` files read at build time. Default `inputs` cover only source-controlled files: a gitignored `.env` did not change the hash until `".env*"` was added to `inputs` (probed). **Good** strict mode (default since 2.0), `inputs: ["$TURBO_DEFAULT$", ".env*"]`, `eslint-plugin-turbo` `turbo/no-undeclared-env-vars` or Biome `noUndeclaredEnvVars` (nursery, Biome ≥2.3.10). **Fix** declare the vars and files. **Gain** none (correctness). **Risk** more misses after the fix, which is correct.
5. **Over-broad global invalidation.** **Check** `globalDependencies` globs (any matching change → "all tasks will miss cache"). Also check for the root workspace's own source/scripts changing often: the root is an implicit dependency of every package since 2.0 ([2.0](https://turborepo.dev/blog/turbo-2-0)). **Good** global deps limited to files that change every task's output; per-task `inputs` with `$TURBO_ROOT$/…` (2.5+) for root files only some tasks read. **Fix** narrow them, and move root scripts/code into a package. **Gain** *typical, unmeasured*. **Risk** under-declaring → wrong hits.
6. **PRs run everything** (topology). **Check** `turbo run` without `--affected`/`--filter=...[…]` when no remote cache exists, and `actions/checkout` without `fetch-depth: 0`. "If the checkout is too shallow, then all packages will be considered changed" ([run](https://turborepo.dev/docs/reference/run)). Even on a full clone, the PR base may exist only as `origin/<base>`, which logs `Failed to resolve base ref 'main' from GitHub Actions event` ([#9320](https://github.com/vercel/turborepo/issues/9320), seen on 2.2.3). **Good** `actions/checkout` with `fetch-depth: 0` and `filter: blob:none` ([constructing CI](https://turborepo.dev/docs/crafting-your-repository/constructing-ci)), `turbo run lint check-types test build --affected`, and the base resolved. **Fix** `futureFlags.githubActionsRemoteBaseRefFallback: true` (2.11.0+), or `TURBO_SCM_BASE=origin/${{ github.base_ref }}`. On GHA, the base is auto-detected (2.2+): the PR base on PRs, the pre-push commit on push. `futureFlags.affectedUsingTaskInputs` (2.8.17+) narrows to tasks whose `inputs` changed. **Gain** unaffected packages' tasks; *typical, unmeasured*. **Risk** a full clone costs checkout time on huge repos (blobless limits it). Required release checks must still run on main (guardrail 1).
7. **Whole jobs that need not run.** **Check** deploy/E2E/Docker jobs with no change gate, or `npx turbo-ignore` (deprecated 2.9). **Fix** gate step: `turbo query affected --packages web --exit-code` (exit 1 = affected, 0 = not, 2 = error; probed `--help`) or parse `.data.affectedPackages.length`. **Gain** whole job minutes; *typical, unmeasured*. **Risk** exit 2 must fail open (run the job).
8. **Duplicate or disabled work.** **Check** `grep -rnE 'turbo (run )?[a-z:-]+.*(--force|--cache=|--no-cache)|TURBO_FORCE|"cache": *false'`, plus a `turbo build` followed by `npm run build -w …`/`pnpm --filter … build` in the same job or a later one, plus one job per package each running setup. **Good** one `turbo run a b c` per job, so tasks share the graph and cache. **Fix** delete the re-runs, drop `--force` from CI, and merge per-package jobs into one turbo job (lane `build-steps.md` §8). `cache: false` is right only for tasks faster than a remote round-trip, huge outputs, or tasks with their own cache ([caching](https://turborepo.dev/docs/crafting-your-repository/caching)). **Gain** the duplicated task time; *typical, unmeasured*. **Risk** none.
9. **Untrusted writes to the remote cache.** **Check** PR workflows with a read-write `TURBO_TOKEN`. **Good** PRs read-only: `TURBO_CACHE=local:rw,remote:r` (2.3+ syntax). Pitfall: the 2.11.10 warning for `TURBO_REMOTE_CACHE_READ_ONLY` suggests `TURBO_CACHE=remote:r`, which **disables the local cache** (omitted source = off; probed: 0 cached). Optional `remoteCache.signature: true` + `TURBO_REMOTE_CACHE_SIGNATURE_KEY` (HMAC-SHA256; failed verification = miss), but it "is not a security feature" ([config](https://turborepo.dev/docs/reference/configuration)). **Gain** none (safety); PR runs lose remote writes. **Risk** PR-to-PR reuse drops.
10. **Serialized typecheck/lint** (typecheck-lint). **Check** `"check-types"`/`"lint"` with `dependsOn: ["^check-types"]`/`["^build"]` and a deep package chain (the summary shows tasks starting only after dependencies finish). **Good** transit nodes: `"transit": {"dependsOn": ["^transit"]}`, `"check-types": {"dependsOn": ["transit"]}`. These run in parallel and still invalidate on dependency source changes. `"check-types": {}` is wrong ([configuring tasks](https://turborepo.dev/docs/crafting-your-repository/configuring-tasks)). 2.10+: `inputs` entry `{"mode": "dependencyOutputs", "globs": ["dist/**/*.d.ts"], "from": ["^check-types"]}` misses only when a dependency's interface changes (the `from` task must declare `outputs` and already be in `dependsOn`). **Gain** critical path ≈ the longest single package instead of the chain; *typical, unmeasured*. **Risk** if a check really needs built dependency output (`^build`), transit gives wrong results.
11. **Concurrency vs cores** (topology, test). **Check** `--concurrency`, `TURBO_CONCURRENCY` or the `concurrency` key (config/env since 2.5.1) against `nproc`. The default is 10 regardless of cores, and `--parallel` is deprecated (2.9) because it ignores the graph and cache. **Fix** `--concurrency=100%` (or `N`) for CPU-light tasks, lower for heavy ones. Cap either turbo or the test runner's workers, not both at max (`test-parallelism.md`). **Gain** measure CPU% (`test-parallelism.md` §1.3). **Risk** OOM.
12. **Docker installs the whole monorepo** (install, docker). **Check** a Dockerfile that has `COPY . .` before install and no `turbo prune`. **Good** stage 1 `turbo prune <app> --docker`. Stage 2 `COPY out/json/ .` → install → `COPY out/full/ .` → `turbo run build`. Install then re-runs only on manifest/lockfile changes ([docker guide](https://turborepo.dev/docs/guides/tools/docker)). `--production` (2.11.0) drops devDependency-only workspace packages. `globalDependencies` files are not copied unless `futureFlags.pruneIncludesGlobalFiles` (2.9+) ([prune](https://turborepo.dev/docs/reference/prune)). turbo must be pinned before install: standalone archive `TURBO_VERSION` (≥2.11.5 only; older: `npm i -g turbo@<repo version>`). Remote cache in Docker: pass the token with `RUN --mount=type=secret,id=turbo_token,env=TURBO_TOKEN` + `docker build --secret id=turbo_token,env=TURBO_TOKEN`, not the guide's `ARG/ENV TURBO_TOKEN`, because Docker says build args/env "persist in the final image" ([secrets](https://docs.docker.com/build/building/secrets/)). **Gain** install layer cached across source-only changes; *typical, unmeasured*. **Risk** a version-mismatched turbo binary prunes differently.
13. **Old turbo in a large repo.** **Check** version < 2.9 with hundreds of packages; `--profile` shows startup dominating. **Fix** upgrade (`npx @turbo/codemod migrate`). **Gain** (cited, vendor, M4 Max) Time to First Task on 1037 packages: 8.1 s (2.8) → 716 ms (2.9) → 394 ms (2.11) ([2.9](https://turborepo.dev/blog/2-9), [2.11](https://turborepo.dev/blog/2-11)), paid per `turbo` invocation. **Risk** future flags and config changes alter the global hash, giving one cold run: "Future flags that change behavior can invalidate the task cache."

## Cache paths
| Cache | Path / setting | Key inputs | Restore order |
|---|---|---|---|
| Local artifacts | `.turbo/cache/<hash>.tar.zst` + `-meta.json` + `-manifest.json` (probed). `cacheDir` / `--cache-dir` / `TURBO_CACHE_DIR`. 1.x: `node_modules/.cache/turbo` | turbo's own hash. For `actions/cache`, the official recipe is `path: .turbo`, `key: ${{ runner.os }}-turbo-${{ github.sha }}`, `restore-keys: ${{ runner.os }}-turbo-` ([GHA guide](https://turborepo.dev/docs/guides/ci-vendors/github-actions)) | Anywhere before `turbo run`. 2.x is outside `node_modules`, so `npm ci` does not wipe it. On 1.x, restore **after** install. Save only on the default branch. A new entry per SHA grows the cache: set `cacheMaxAge` (`"7d"`) / `cacheMaxSize` (`"10GB"`), 2.10+, default `"0"` = off; "We expect to enable it by default in Turborepo 3.0" ([config](https://turborepo.dev/docs/reference/configuration)). |
| Remote | Vercel (`apiUrl` default `https://vercel.com`) or self-hosted (`TURBO_API`, OpenAPI v8 endpoints). Community servers: `ducktors/turborepo-remote-cache`, `brunojppb/turbo-cache-server` ([remote caching](https://turborepo.dev/docs/core-concepts/remote-caching)) | same hash; env `TURBO_TOKEN`, `TURBO_TEAM` (slug) or `TURBO_TEAMID` | No restore step. The OIDC/env setup must precede the first turbo step. `remoteCache.timeout` 30 s, `uploadTimeout` 60 s. `--cache-workers` 10. |
| Run summaries / logs | `.turbo/runs/*.json`, `<pkg>/.turbo/turbo-<task>.log` (probed) | n/a | Artifacts, not caches. Exclude them from `outputs`. |
Cache `.turbo` with `actions/cache` only when there is no remote cache; caching both duplicates the work. Turbo artifacts hold `outputs` + logs, so secrets printed to logs are cached too ([remote caching](https://turborepo.dev/docs/core-concepts/remote-caching)).

## Version traps
- **2.0** (2024-06-04): `pipeline` → `tasks`; `outputMode` → `outputLogs`; `dotEnv`/`globalDotEnv` removed (put `.env*` in `inputs`); **strict env mode default** (CI-vendor vars filtered unless declared); cache dir `node_modules/.cache` → `.turbo/cache`; `--scope`/`--ignore` removed; root `packageManager` required; root workspace is an implicit dependency of all packages; `engines` hashed; directory globs `dist` = `dist/**` ([2.0](https://turborepo.dev/blog/turbo-2-0)). Migrate with `npx @turbo/codemod migrate`.
- **2.1**: `--affected` (default `...[main...HEAD]`, base `TURBO_SCM_BASE`/`TURBO_SCM_HEAD`); `cacheDir`/`envMode` keys. **2.2**: GHA base auto-detect; empty-outputs warning. **2.3**: `--cache=local:rw,remote:rw` (default) replaces `--no-cache` (→ `local:r,remote:r`), `--remote-only` (→ `remote:rw`), `--remote-cache-read-only`/`TURBO_REMOTE_CACHE_READ_ONLY` (→ `local:rw,remote:r`). On 2.11.10, the old forms still work but print a deprecation warning (probed for `--no-cache`, `--remote-cache-read-only` and `TURBO_REMOTE_CACHE_READ_ONLY`).
- **2.5**: `turbo.jsonc`, `$TURBO_ROOT$`, `--continue=dependencies-successful`, `with`; 2.5.1 adds `concurrency`/`TURBO_CONCURRENCY`. **2.7**: `$TURBO_EXTENDS$`, `extends` by package name; 2.7.4 shares the local cache across git worktrees.
- **2.9** (blog 2026-03-25): daemon no longer used by `turbo run` (`daemon` key, `--daemon`, `TURBO_DAEMON` deprecated; removal in 3.0); `--parallel`, `turbo-ignore`, `turbo scan`, and `--graph` png/jpg/pdf/json deprecated; `turbo query` stable; `--profile` writes `.md`; future flags `affectedUsingTaskInputs` (2.8.17), `filterUsingTasks`, `pruneIncludesGlobalFiles`, `longerSignatureKey` (2.8.14).
- **2.10** (2026-06-24): `--affected` + `--filter` = intersection; `cacheMaxAge`/`cacheMaxSize`; `inputs` modes `jit`/`dependencyOutputs`. **2.11** (2026-09-18): `githubActionsRemoteBaseRefFallback`, `prune --production`, Cargo/uv/Go workspaces (experimental); top-level `packageManager` will be dropped in a future major (use `devEngines.packageManager`); 2.11.5 adds standalone binaries (`TURBO_VERSION`).
- **3.0 (not released)**: local cache eviction is "expected" to be on by default; the `daemon` key and `--graph` png/jpg/pdf/json are slated for removal in 3.0, and other deprecated flags "in a future major version". The 2.9 blog says the goal of future flags is that upgrading to 3.0 needs only a PR that deletes the flags and bumps the version (paraphrased).
