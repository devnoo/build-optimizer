# go — optimize-build stack reference
Use when: detect-stack.sh reported `go`. Lanes: install, build, typecheck-lint, test, cache.

Checked 2026-11-18. Latest that day: Go **1.27.4** (1.26.11 still supported), `actions/setup-go` **v7.1.0**, golangci-lint **v2.15.0**, `golangci/golangci-lint-action` **v9.3.0**, gotestsum **v1.13.0**. **(local)** means read that day from `go help …` on go1.27.3 or from the Go source at tag `go1.27.4`. **(cited)** means linked vendor text. **(heuristic)** means typical but unmeasured, so measure it on the repo. Worker counts and `t.Parallel` are in `test-parallelism.md` §8.

## Measure
- **Which commands run:**
  ```bash
  grep -nE 'go (build|test|vet|generate|install|run|mod download)|golangci-lint|gotestsum|setup-go|GOFLAGS|GOCACHE|-race|-count|-coverpkg|-ldflags|-p[ =]1' .github/workflows/*.y*ml Makefile* Taskfile* 2>/dev/null
  go env GOCACHE GOMODCACHE GOFLAGS GOPROXY; go list ./... | wc -l; go list -m all | wc -l
  ```
- **Compile vs run.** The `ok  pkg  1.2s` line is the test *run* only. Compiling and linking each test binary is not in it. Split them: `go test -count=1 -run '^$' ./...` builds and links every test binary and runs no test; the rest of the step is run time.
- **Slowest packages and tests:** `gotestsum --jsonfile t.json -- ./...`, then `gotestsum tool slowest --jsonfile t.json --threshold 500ms`. Without gotestsum: `go test -json ./... > t.json` and rank `Elapsed` on the `"Action":"pass"` events.
- **Cache hits.** A reused test result prints `(cached)` in place of the time (local, `go help test`). Count them in the CI log: `grep -c '(cached)' job.log`. Zero on a job with a restored `GOCACHE` means check 2.
- **Why a test result was not reused:** `GODEBUG=gocachetest=1 go test ./pkg` prints the decision; `GODEBUG=gocachehash=1` prints every input to the cache key (local, `go help cache`).
- **setup-go log:** `Cache restored from key: setup-go-…` or `Cache is not found`.

## Checks
1. **Build cache missing or frozen.** **Check**: no `actions/setup-go`, or `cache: false`, or the key never changes. **Facts**: setup-go caches `GOMODCACHE` and `GOCACHE` by default. Its key is `setup-go-<platform>-<arch>-<imageOS>go-<version>-<hash>` with **no restore-keys** ([cache-restore.ts](https://github.com/actions/setup-go/blob/main/src/cache-restore.ts)), and since v6 the hash is of `go.mod` ([README](https://github.com/actions/setup-go)). Cache entries are immutable, and "By default, this cache is not updated based on source changes" ([advanced usage](https://github.com/actions/setup-go/blob/main/docs/advanced-usage.md)). So the saved build cache holds what one job compiled on the commit that first produced that key. Every later commit recompiles whatever changed since, and a `go.mod` change starts fully cold. **Good**: the module cache follows `go.sum`, and the build cache is refreshed from the default branch. **Fix**: small repos: `cache-dependency-path: go.sum`. Large repos: `cache: false` plus `actions/cache/restore` on both directories with key `go-<os>-<arch>-<go version>-<hashFiles('go.sum')>-<github.sha>` and a `restore-keys` prefix, saved from the default branch only (fix A in `ci-github-caching.md`). **Gain**: the compile time of unchanged packages. Measure the compile-only command cold and warm (heuristic). **Risk**: several jobs saving one key race, and the first to finish wins, even if it compiled the least. Let one job write and the others restore ([parallel builds](https://github.com/actions/setup-go/blob/main/docs/advanced-usage.md)).
2. **The test result cache never hits in CI.** **Facts** (local, `go help test`): results are cached only in package-list mode (`go test ./...`, not a bare `go test`), only for passing packages, and only when every flag is in the cacheable set: `-benchtime, -coverprofile, -cpu, -failfast, -fullpath, -list, -outputdir, -parallel, -run, -short, -skip, -timeout, -v`. `-count=1` is "the idiomatic way to disable test caching". A match also needs "the same test binary", and tests that open files in the module or read environment variables match only when those are unchanged. For an opened regular file Go hashes **size, mode and mtime, not content**, and a file modified under 2 s ago disables caching (local, [`hashOpen`](https://github.com/golang/go/blob/go1.27.4/src/cmd/go/internal/test/test.go)). **Check**, in this order:
   - `-count=1` or `-shuffle` on the PR test command.
   - `-ldflags "-X …=$GITHUB_SHA"` on `go test`: a new test binary every commit.
   - Tests that read `testdata/` or fixtures: `actions/checkout` gives every file a fresh mtime, so they miss even with `GOCACHE` restored.
   - Tests that read per-run environment variables (`GITHUB_SHA`, `GITHUB_RUN_ID`).

   **Fix**: restore `GOCACHE` (check 1), drop the flag from PR runs, and for file-reading tests set each file's mtime to its last commit time after checkout (`git restore-mtime`, needs full history). **Gain**: unchanged packages print `(cached)`. It scales with the share of untouched packages (heuristic). **Risk**: Go tracks only files inside the module and environment variables. A test that depends on a database, the network or the clock gets a stale pass, so keep `-count=1` on integration packages. Never touch all files to one constant time: an edit that keeps the file size would then reuse a stale result.
3. **`-race` on every leg.** **Fact**: "memory usage may increase by 5-10x and execution time by 2-20x" ([race detector](https://go.dev/doc/articles/race_detector)). **Check**: `-race` in every matrix leg or in both a unit and an integration job. **Fix**: keep `-race` on one leg (latest Go, linux/amd64) and drop it from the others. **Gain**: measure one leg with and without. **Risk**: a race that only shows on another OS or arch surfaces later. Do not remove the race leg (guardrail 1).
4. **Vet runs twice.** **Fact** (local): `go test` runs `go vet` while building each test binary, with the subset "atomic, bools, buildtag, directive, errorsas, ifaceassert, nilfunc, printf, stdversion, stringintconv, and tests". `-vet=off` disables it. **Check**: the pipeline also runs `go vet ./...` or golangci-lint with `govet`. **Fix**: `go test -vet=off` in the test job. **Gain**: compare the compile-only command with and without the flag (heuristic, small to moderate). **Risk**: none while the lint job is a required check.
5. **Whole-suite serialisers.** `-p 1` or `-parallel 1`. `-p` defaults to GOMAXPROCS (local, `go help build`). Blockers and remedies: `test-parallelism.md` §5 and §8.
6. **`-coverpkg=./...`.** **Fact** (local): by default each test analyses "only the package being tested". `-coverpkg` widens that to every matched package for every test binary. **Check**: `-coverpkg` on the PR test command. **Fix**: per-package coverage on PRs, and the wide profile on the default branch or nightly. **Gain**: measure both (heuristic). **Risk**: PR coverage numbers drop for packages tested only from other packages.
7. **golangci-lint.** **Check**: how it is installed and whether its caches are warm. **Facts**: the action's default `install-mode: binary` downloads a release; `goinstall` compiles it and "is not recommended". The action caches analysis results, invalidated every `cache-invalidation-interval` days (default 7), and "We rely on `actions/setup-go` for Go module cache" ([README](https://github.com/golangci/golangci-lint-action)). **Good**: setup-go with caching runs before the action in the lint job. **Fix**: replace `go install …/golangci-lint` or `go run` with the action. `only-new-issues: true` changes what is *reported*, so claim no speed gain from it. **Gain**: the linter compile, often minutes (heuristic). **Risk**: none.
8. **Tools compiled every run.** **Check**: `go install tool@version` or `go run tool@version` steps (mockgen, sqlc, protoc plugins). **Fix**: a prebuilt binary, or the `tool` directive in `go.mod` (Go ≥1.24, [release notes](https://go.dev/doc/go1.24#tools)) so tools build through the same cached module graph. **Gain**: the compile time of each tool on a cold cache (heuristic). **Risk**: tool dependencies join the module graph.
9. **Compiling the same packages in several jobs.** **Fact** (local, `go help cache`): one `GOCACHE` serves `go build`, `go vet` and `go test`, and is "safe for concurrent invocations". **Check**: separate build, vet and test jobs, each starting from a cold or frozen cache. **Fix**: one job that runs them in sequence shares the compile work; or give all jobs the same restored cache (check 1). For a `GOOS`/`GOARCH` build matrix without cgo, cross-compile on one Linux runner instead of one runner per OS. **Gain**: one full compile per removed job (heuristic). **Risk**: a longer single job. Compare the new critical path first (`build-steps.md` §8).
10. **Module download.** **Check**: a `go mod download` step, or a long first `go` command, with `Cache is not found` in the setup-go log. `GOFLAGS=-mod=mod` or `GOPROXY=direct` forces VCS fetches. **Fix**: the cache from check 1. For private modules, a proxy instead of `direct`. **Gain**: the download time (heuristic). **Risk**: none.

## Cache paths
| Cache | Path | Key inputs | Notes |
|---|---|---|---|
| Module cache | `go env GOMODCACHE` (`~/go/pkg/mod`) | OS, Go version, `go.sum` hash | A download cache: prefix restores are safe |
| Build and test-result cache | `go env GOCACHE` (`~/.cache/go-build` on Linux) | OS, arch, Go version, `go.sum` hash; add `github.sha` with a prefix restore to keep it fresh | Go deletes entries unused for 5 days, checking at most once a day (local, [cache.go](https://github.com/golang/go/blob/go1.27.4/src/cmd/go/internal/cache/cache.go)) |
| golangci-lint analysis | `golangci-lint cache status` prints it | managed by the action, 7-day interval | Needs a warm `GOCACHE` beside it |
| Remote build cache | `GOCACHEPROG=<command>` | the program decides | An external cache program ([Go 1.24](https://go.dev/doc/go1.24#gocacheprog)); use it for self-hosted or shared caches |

## Version traps
- **setup-go v6**: Node 24 (runner ≥2.327.1), honours the `toolchain` directive, and hashes `go.mod` instead of `go.sum`. **v7** only moved the action to ESM, with no behaviour change ([README](https://github.com/actions/setup-go)).
- **golangci-lint-action**: v7.0.0 supports golangci-lint v2 only, v9.0.0 needs Node 24, and v5.0.0 removed `skip-pkg-cache`/`skip-build-cache` because setup-go owns those caches.
- **Go 1.25**: GOMAXPROCS follows the cgroup CPU limit ([release notes](https://go.dev/doc/go1.25#container-aware-gomaxprocs)). Older versions oversubscribe in containers with a CPU quota.
- **Go 1.24**: `tool` directives in `go.mod`, and `GOCACHEPROG` left its experiment.
