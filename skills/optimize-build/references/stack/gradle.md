# gradle — optimize-build stack reference
Use when: detect-stack.sh reported `gradle`. Lanes: install, build, typecheck-lint, test, topology, cache. Test runtime cost (Spring contexts, Testcontainers, forks) is in [jvm.md](jvm.md).

Checked 2026-11-18. Latest that day: Gradle **9.9.1**, `gradle/actions` **v6.4.1**, `actions/setup-java` **v6.3.0**, Kotlin **2.4.21**. **(cited)** means linked vendor text, read that day from the Gradle 9.9.1 user guide and the action docs. **(heuristic)** means typical but unmeasured, so measure it on the repo. No JDK was available for local runs, so nothing here is marked local.

## Measure
- **Which invocations run:**
  ```bash
  grep -nE 'gradlew?( |$)|setup-gradle|setup-java|cache:|--no-daemon|--rerun-tasks|--refresh-dependencies|--no-build-cache|clean|-x test|--parallel|--scan|cache-(read-only|provider|encryption-key)' .github/workflows/*.y*ml
  cat gradle.properties 2>/dev/null; grep -c . settings.gradle* 2>/dev/null
  grep -rnE 'maxParallelForks|forkEvery|maxHeapSize|jvmArgs|kapt|ksp|upToDateWhen|outputs\.cacheIf|dependencyLocking|latest\.(release|integration)|[0-9]\.\+' --include='*.gradle' --include='*.gradle.kts' . | head -40
  ```
- **Task outcomes.** Run with `--console=plain`: every task prints its outcome (`UP-TO-DATE`, `FROM-CACHE`, `NO-SOURCE`, or none when it executed), and the build ends with `N actionable tasks: X executed, Y from cache, Z up-to-date`. On CI, `X executed` near N with a restored cache means checks 2 or 3.
- **Build Scan.** `--scan` publishes a timeline with configuration time, per-task time, cache hits and test durations. setup-gradle can publish one per job with `build-scan-publish: true`, `build-scan-terms-of-use-url: 'https://gradle.com/terms-of-service'` and `build-scan-terms-of-use-agree: 'yes'`, and it adds the link to the job summary ([setup-gradle](https://github.com/gradle/actions/blob/main/docs/setup-gradle.md)). A scan uploads build data to gradle.com, so get the user's go-ahead first.
- **Without publishing:** `--profile` writes an HTML report under `build/reports/profile/` with configuration, dependency resolution and task times ([CLI](https://docs.gradle.org/current/userguide/command_line_interface.html)).
- **Why a cacheable task missed:** `-Dorg.gradle.caching.debug=true` logs every input fingerprint and the cache key per task. Compare two runs, starting at the first executed cacheable task, since later misses cascade from it ([cache debugging](https://docs.gradle.org/current/userguide/build_cache_debugging.html)).
- **Test results:** `build/test-results/**/*.xml`, ranked with the JUnit script in `ci-github-timings.md` §6.

## Checks
1. **Several Gradle invocations in one job.** **Check**: separate steps for `./gradlew assemble`, `./gradlew test`, `./gradlew check`. **Facts**: "The configuration phase always executes, regardless of which tasks run", and on CI "long-lived agents benefit, but short-lived ones may not" from the daemon ([performance](https://docs.gradle.org/current/userguide/performance.html)). Each invocation pays startup and configuration; with `--no-daemon` it also pays a JVM start. **Fix**: one invocation with all tasks (`./gradlew check assemble`), without `clean`. **Gain**: one startup plus configuration per removed invocation. Read the configuration time from `--profile` (heuristic). **Risk**: one failing task hides later ones unless `--continue` is set.
2. **Build cache off, or it never hits.** **Facts**: "By default, Gradle does not use the Build Cache"; enable it with `org.gradle.caching=true` ([performance](https://docs.gradle.org/current/userguide/performance.html)). On hosted runners the local cache directory (`caches/build-cache-1`) only survives if setup-gradle restores it, and by default only default-branch jobs write it ([setup-gradle](https://github.com/gradle/actions/blob/main/docs/setup-gradle.md)). **Check**: the `from cache` count in the summary line; `--rerun-tasks`, `--no-build-cache` or `cleanTest` in the CI command; tasks with `outputs.upToDateWhen { false }`. Causes of misses the docs list: absolute paths among inputs, timestamps in generated files, non-repeatable outputs, and build-logic changes ([cache debugging](https://docs.gradle.org/current/userguide/build_cache_debugging.html)). **Fix**: turn the cache on in `gradle.properties`, drop the forcing flags from PR runs, and for many modules or many branches add a remote cache with push from CI only. With a remote cache, disable the local one in CI (setup-gradle recommends this). **Gain**: unchanged modules' compile and test tasks become `FROM-CACHE`, usually the largest single win in multi-module builds (heuristic). **Risk**: a task with undeclared inputs restores a stale output. Tests that hit external systems must stay non-cacheable on purpose (guardrail 1).
3. **Configuration cache off, or not persisted.** **Fact**: "By default, Gradle does not use the configuration cache"; enable with `org.gradle.configuration-cache=true` ([performance](https://docs.gradle.org/current/userguide/performance.html)). **Check**: the log line about reusing or storing the configuration cache, and whether `cache-encryption-key` is set: setup-gradle stores configuration-cache data in the Actions cache encrypted with that key. **Fix**: enable it, fix the reported incompatible plugins, and add the secret (`openssl rand -base64 16`). **Gain**: the configuration phase on every invocation that hits (heuristic). **Risk**: plugins that read environment or files at configuration time need changes ([configuration cache](https://docs.gradle.org/current/userguide/configuration_cache.html)).
4. **Serial task execution.** **Fact**: "by default, Gradle runs only one task at a time"; enable with `org.gradle.parallel=true` ([performance](https://docs.gradle.org/current/userguide/performance.html)). **Check**: a multi-project build without it. **Gain**: bounded by the project graph's width and the runner's cores. On 2 vCPU it is small (heuristic). **Risk**: tasks in different projects that share ports, files or a database now overlap.
5. **Dependency cache missing or doubled.** **Check**: no setup-gradle; or `setup-java` with `cache: gradle` *and* setup-gradle; or a manual `actions/cache` on `~/.gradle` saved from PRs. **Facts** ([setup-gradle](https://github.com/gradle/actions/blob/main/docs/setup-gradle.md)): setup-gradle caches downloaded dependencies, compiled build scripts, transforms and the local build cache from the Gradle User Home. The default `cache-provider: enhanced` is proprietary (free for public repos); `basic` is MIT, uses the key `setup-java-<os>-<arch>-gradle-<hash of build files>` and **has no restore keys**, so any build-file change starts cold. Combining it with other mechanisms "may interfere". **Fix**: setup-gradle alone, after setup-java without `cache:`. State the licence choice in the finding instead of deciding it. **Gain**: the dependency download and build-script compile (heuristic). **Risk**: none.
6. **Heap too small, or the memory budget too big.** **Fact**: "By default, Gradle reserves 512MB of heap space for your build" ([performance](https://docs.gradle.org/current/userguide/performance.html)). **Check**: no `org.gradle.jvmargs`; GC warnings or `Expiring Daemon because JVM heap space is exhausted` in the log; exit 137. Add up the daemon heap, the Kotlin daemon and `maxParallelForks × maxHeapSize` against the runner's RAM (8 GB on a private-repo standard runner). **Fix**: set `org.gradle.jvmargs=-Xmx…` explicitly and size the test forks to fit. **Gain**: avoids GC thrash and OOM retries (heuristic). **Risk**: over-allocating pushes the runner into swap.
7. **Dependency resolution hits the network every run.** **Check**: `--refresh-dependencies` in CI; dynamic versions (`1.+`, `latest.release`) or `-SNAPSHOT` dependencies; many repositories with the busiest one last. **Facts**: "By default, Gradle caches dynamic versions for 24 hours", and "Gradle searches repositories in the order they are declared" ([performance](https://docs.gradle.org/current/userguide/performance.html)). **Fix**: remove the flag, pin or lock versions (`dependencyLocking`), order repositories by use and add content filters. **Gain**: the resolution time shown in `--profile` (heuristic). **Risk**: none; locked versions also make cache keys stable.
8. **Test task settings.** Forks and parallelism: `test-parallelism.md` §8 and [jvm.md](jvm.md). **Facts**: "Forking a JVM is an expensive operation" (`forkEvery`), and "Gradle generates HTML and JUnit XML test reports by default" ([performance](https://docs.gradle.org/current/userguide/performance.html)). **Check**: `forkEvery = 1`; HTML reports generated but never uploaded. **Fix**: `forkEvery = 0`, and `reports.html.required = false` in CI when only the XML is consumed. **Gain**: the per-class JVM start, and the report time (heuristic, the second is small). **Risk**: tests that leak static state relied on the fresh JVM.
9. **Recompiling downstream projects.** **Facts**: "When an implementation dependency changes, Gradle does not recompile downstream consumers", and annotation processors must be declared explicitly "to take full advantage of compile avoidance" ([performance](https://docs.gradle.org/current/userguide/performance.html)). **Check**: `api(` used where `implementation(` would do; processors on the compile classpath; kapt in Kotlin modules. **Fix**: `implementation` by default, `annotationProcessor` configurations, and KSP in place of kapt where the processor supports it. **Gain**: fewer modules recompile per change (heuristic). **Risk**: consumers that used a transitive `api` type stop compiling until they declare it.
10. **JDK toolchain downloaded per run.** **Check**: a `toolchain { languageVersion }` that differs from the JDK setup-java installed. Gradle then provisions a JDK into `~/.gradle/jdks`, which setup-gradle does not cache by default. **Fix**: install the toolchain's version with setup-java, or add `jdks` to `gradle-home-cache-includes` ([setup-gradle](https://github.com/gradle/actions/blob/main/docs/setup-gradle.md)). **Gain**: one JDK download per job (heuristic). **Risk**: none.

## Cache paths
| Cache | Path | Key inputs | Notes |
|---|---|---|---|
| Dependencies, build scripts, transforms | `~/.gradle/caches` (`modules-2`, `kotlin-dsl`, `transforms-*`, `jars-*`) | managed by setup-gradle; written from the default branch only | Stop daemons before a manual save: held locks break archiving |
| Local build cache | `~/.gradle/caches/build-cache-1` | task inputs | Part of the setup-gradle cache; disable it in CI when a remote cache exists |
| Wrapper distribution | `~/.gradle/wrapper` | `gradle-wrapper.properties` hash | |
| Configuration cache | `.gradle/configuration-cache` in the project | needs `cache-encryption-key` to be stored by setup-gradle | |
| Toolchain JDKs | `~/.gradle/jdks` | opt in with `gradle-home-cache-includes` | |
| `build/` directories | per project | — | Do not cache: the build cache already covers reusable outputs |

## Version traps
- **Gradle 9**: the build cache, the configuration cache and parallel execution are all still opt-in in 9.9.1 (quotes above).
- **setup-gradle v6**: enhanced caching is the default provider and is proprietary; `cache-provider: basic` is the MIT path. Non-default branches read the cache and do not write it.
- **setup-java v6**: cache keys now include `gradle.properties`, `cache-read-only: true` restores without saving, and the JDK itself is cached whenever `cache` is set ([README](https://github.com/actions/setup-java)). Its Gradle cache has no restore keys.
- **kapt → KSP**: KSP needs processors that ship a KSP implementation. Check each processor before proposing the switch.
