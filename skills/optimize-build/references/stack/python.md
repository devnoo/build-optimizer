# python — optimize-build stack reference
Use when: detect-stack.sh reported `python`. Lanes: install, typecheck-lint, test, docker, cache.

Checked 2026-11-18. Latest that day: uv **0.13.9**, `astral-sh/setup-uv` **v10.3.3**, `actions/setup-python` **v7.1.0**, pip **26.3**, Poetry **2.5.1**, pytest **9.2.0**, pytest-xdist **3.8.0**, coverage.py **7.17.3**, mypy **2.4.1**, ruff **0.17.5**, ty **0.0.105** (still pre-1.0). **(local)** means read that day from the `--help` output of pytest 9.2.0, pytest-xdist 3.8.0, mypy 2.4.1 and uv 0.13.8. **(cited)** means linked vendor text; vendor benchmarks are not independent. **(heuristic)** means typical but unmeasured, so measure it on the repo. ## Measure
- **Which tools run:**
  ```bash
  ls uv.lock poetry.lock Pipfile.lock requirements*.txt pyproject.toml tox.ini noxfile.py .pre-commit-config.yaml 2>/dev/null
  grep -nE 'pip install|uv (sync|pip|run)|poetry install|pipenv|tox|nox|pytest|coverage|--cov|mypy|ruff|flake8|pylint|black|isort|pre-commit|setup-(python|uv)|cache:|enable-cache' .github/workflows/*.y*ml Makefile* 2>/dev/null
  grep -nE 'addopts|testpaths|norecursedirs|-n |--cov|--dist|filterwarnings' pyproject.toml pytest.ini setup.cfg tox.ini 2>/dev/null
  ```
- **Slowest tests and fixtures:** `pytest --durations=25 --durations-min=0.5`. It lists setup, call and teardown separately, so an expensive fixture shows as a `setup` row (local: "Show N slowest setup/test durations (N=0 for all)").
- **Collection and import cost:** time `pytest --collect-only -q`. For imports: `python -X importtime -c 'import <package>' 2> imp.log`, then sort by the cumulative column.
- **Per-file ranking:** `--junitxml=reports/junit.xml`, then the JUnit ranker in `ci-github-timings.md` §6.
- **Install split:** uv prints `Resolved N packages in …`, `Prepared N packages in …` (download and build) and `Installed N packages in …` (local). In pip logs, `Building wheel for <pkg>` marks a source build and `Using cached` marks a cache hit.
- **Cache evidence:** setup-uv and setup-python both expose a `cache-hit` output and log the restored key.

## Checks
1. **Install resolves instead of replaying a lockfile.** **Check**: `pip install -r requirements.txt` with unpinned or ranged versions, or `uv sync` without a lock flag. **Facts**: `uv sync --locked` asserts "that the `uv.lock` will remain unchanged", and `--frozen` syncs "without updating the `uv.lock` file" (local). With ranged requirements pip always looks for newer versions, so a restored cache "will not be used if the requirements.txt file is not updated for a long time" ([setup-python](https://github.com/actions/setup-python)). **Fix**: commit a lockfile and install frozen: `uv sync --locked`, `poetry install` with `poetry.lock`, or a compiled `requirements.txt` with exact pins. **Gain**: the resolution time, plus a cache that stays valid (heuristic). **Risk**: none. A stale lock now fails the job.
2. **pip where uv would do.** **Check**: `pip install` dominates the install step. **Fix**: `uv pip install -r requirements.txt` is a drop-in; `uv sync` for projects with a `uv.lock`. **Gain**: vendor claim of "10-100x faster than pip" ([uv](https://docs.astral.sh/uv/)) (cited). Measure the step. **Risk**: resolver differences on pre-releases and multiple indexes, so diff the resolved versions once.
3. **No dependency cache, or one that stores the wrong thing.** **Facts**:
   - setup-python caches nothing unless `cache:` is set. `cache: pip` stores pip's global cache, so packages are still installed every run. `poetry` and `pipenv` store the virtualenv. The pip key has a prefix restore key; the poetry key has none ([pip-cache.ts](https://github.com/actions/setup-python/blob/main/src/cache-distributions/pip-cache.ts), [poetry-cache.ts](https://github.com/actions/setup-python/blob/main/src/cache-distributions/poetry-cache.ts)).
   - setup-uv: `enable-cache: auto` is on for GitHub-hosted runners except `release`, tag push, `pull_request_target` and `workflow_run`. The key holds arch, platform, OS version, Python version and a hash of `cache-dependency-glob` (default: `uv.lock`, `pyproject.toml`, requirements and constraints files). "The entire uv cache is uploaded … by default" ([caching](https://github.com/astral-sh/setup-uv/blob/main/docs/caching.md)).

   **Good**: one cache per job, keyed on the lockfile and the Python version. **Fix**: for uv set `prune-cache: true`, or run `uv cache prune --ci` before a manual save. It drops pre-built wheels and keeps wheels built from source, because it is "often faster to omit pre-built wheels from the cache" ([uv cache](https://docs.astral.sh/uv/concepts/cache/)). **Gain**: the download and build share of the install (heuristic). **Risk**: with a slow or private index, pruned wheels are downloaded again every run, so compare both.
4. **Source builds on every run.** **Check**: `Building wheel for …` lines, or a long `Prepared` phase. Causes: a Python version newer than the dependency's wheels, an Alpine (musl) image, or arm64 runners without arm64 wheels. **Fix**: pick a Python version and base image the heavy dependencies ship wheels for. Keep the built wheels in the cache (check 3 does this). Add `--only-binary :all:` to fail fast when a wheel is missing. **Gain**: the native compile, often minutes for scientific or crypto stacks (heuristic). **Risk**: `--only-binary` blocks packages that only publish sdists.
5. **Collection walks too much.** **Check**: `pytest --collect-only -q` takes more than a few seconds, and `testpaths` is unset. `testpaths` are the "Directories to search for tests when no files or directories are given on the command line" (local). Without it pytest recurses from the rootdir. **Fix**: set `testpaths`, extend `norecursedirs`, and move heavy imports out of top-level `conftest.py`, which every xdist worker imports. **Gain**: collection time, paid once per worker (heuristic). **Risk**: tests outside `testpaths` stop running. Compare the collected count before and after.
6. **Fixture cost.** **Check**: `setup` rows at the top of `--durations`: database creation, app factories, containers, large fixture files. **Fix**: widen the scope (`session`, `module`), or one database per xdist worker (`test-parallelism.md` §5). Django: `--no-migrations` builds tables from the models instead of replaying migrations, and `--reuse-db` keeps the database between runs ([pytest-django](https://pytest-django.readthedocs.io/en/latest/database.html)). `--reuse-db` only helps where the database outlives the job. **Gain**: the migration time per worker (heuristic). **Risk**: `--no-migrations` no longer tests the migrations, so keep one job that runs them (guardrail 1). Wider fixture scopes leak state between tests.
7. **Coverage tracer.** **Facts** ([coverage config](https://coverage.readthedocs.io/en/latest/config.html)): the `sysmon` core uses `sys.monitoring`, is "Only available in Python 3.12+, and the default in Python 3.14+". It "does not yet support plugins, dynamic contexts, or some concurrency libraries", and "In Python 3.12 and 3.13, it does not support branch coverage". The `[run] core` setting exists since coverage 7.9; before that it was the `COVERAGE_CORE` env var. **Check**: Python 3.12 or 3.13, line coverage only, coverage on in every matrix leg. **Fix**: `COVERAGE_CORE=sysmon` there, or collect coverage in one leg only. **Gain**: time the test step with and without `--cov` to size it (heuristic). **Risk**: the limits quoted above.
8. **Type checking from cold.** **Facts** (local): mypy caches per module in `.mypy_cache`, `--sqlite-cache` keeps it in one file, and mypy 2.4 has `-n/--num-workers` ("Number of separate mypy worker processes, or 'auto'"). A fresh checkout does not invalidate the cache: when a source file's mtime differs, mypy compares its content hash before discarding the entry ([build.py](https://github.com/python/mypy/blob/master/mypy/build.py)). **Check**: no cache for `.mypy_cache`, and `mypy --version` not showing `compiled: yes`. **Fix**: restore `.mypy_cache` with a key on the mypy version, the Python version and the lockfile hash, plus `github.sha` with a prefix restore ([remote cache](https://mypy.readthedocs.io/en/stable/additional_features.html#using-a-remote-cache-to-speed-up-mypy-runs)). Add `--skip-cache-mtime-checks` only when `mypy -v` logs `data cache is modified`: that means the cache store did not keep the mtimes of the cache files themselves. On ≥4 vCPU try `--num-workers auto`. **Gain**: unchanged modules are not rechecked (heuristic). **Risk**: a cache from another mypy version is ignored, so keep the version in the key. Do not replace a required mypy check with a pre-1.0 checker (ty) without the user's decision.
9. **A chain of single-purpose linters.** **Check**: flake8, isort, black and pylint as separate steps or pre-commit hooks. **Fix**: `ruff check` and `ruff format` in one step. **Gain**: vendor claim of "10-100x faster" than the tools it replaces ([ruff](https://docs.astral.sh/ruff/)) (cited). **Risk**: rule parity. Ruff does not implement every pylint rule, so list the dropped rules in the finding.
10. **pre-commit rebuilds hook environments.** **Check**: `pre-commit run` in CI without a cache on `~/.cache/pre-commit`. **Fix**: cache that directory keyed on the Python version and `hashFiles('.pre-commit-config.yaml')` ([pre-commit CI](https://pre-commit.com/#github-actions-example)). **Gain**: the environment install of every hook (heuristic). **Risk**: none.
11. **tox or nox runs every environment in one job.** **Check**: one job runs `tox` or `nox` across several Python versions in sequence, each creating a virtualenv with pip. **Fix**: one matrix leg per environment, the `tox-uv` plugin or `nox --default-venv-backend uv` for environment creation, and `tox run-parallel` when legs must stay in one job. **Gain**: wall-clock ≈ the slowest environment instead of the sum (heuristic). **Risk**: more billed minutes from per-job setup (`build-steps.md` §8).
12. **Docker.** **Check**: `COPY . .` before `pip install` or `uv sync`. **Fix**: the two-step sync from the [uv Docker guide](https://docs.astral.sh/uv/guides/integration/docker/): `uv sync --frozen --no-install-project` as its own layer with the lockfile bind-mounted and a cache mount, then copy the source and run `uv sync --locked`. With a cache mount set `UV_LINK_MODE=copy`: the mount is a separate filesystem, so uv cannot link files from it. Set `UV_COMPILE_BYTECODE=1` for images that start often; it trades a longer install for faster startup (cited, same guide). **Gain**: a source-only change skips the dependency install (heuristic). **Risk**: cache mounts start empty on hosted runners ([docker.md](docker.md) check 3).

## Cache paths
| Cache | Path | Key inputs | Notes |
|---|---|---|---|
| uv | `~/.cache/uv` (`UV_CACHE_DIR`) | OS and version, arch, Python version, hash of `uv.lock`/`pyproject.toml`/requirements | Prune with `uv cache prune --ci` before saving |
| pip | `pip cache dir` (`~/.cache/pip`) | OS, Python version, requirements hash; prefix restore is safe | Downloads and locally built wheels, not the environment |
| Poetry or pipenv virtualenv | `.venv` (with `virtualenvs.in-project true`) | full Python version, lockfile hash; **no** prefix restore | An installed tree: a partial restore is wrong state |
| mypy | `.mypy_cache` | mypy version, Python version, lockfile hash, `github.sha` with prefix restore | Survives a fresh checkout (content hash); the store must keep the cache files' mtimes |
| pre-commit | `~/.cache/pre-commit` | Python version, hash of `.pre-commit-config.yaml` | |
| ruff, pytest | `.ruff_cache`, `.pytest_cache` | — | Not worth caching in CI: ruff is fast cold, and `.pytest_cache` only feeds `--lf`/`--ff` (heuristic) |

## Version traps
- **setup-uv v10**: `enable-cache: auto`, `prune-cache: false` and `save-cache: auto` (no save on `merge_group`) are the defaults ([README](https://github.com/astral-sh/setup-uv)). Older majors differ, so read the pinned version's `action.yml`.
- **coverage.py**: `sysmon` is the default core only on Python 3.14+. On 3.12 and 3.13 it is opt-in and has no branch coverage.
- **mypy 2.x**: adds `--num-workers` and a fixed-format cache (`--no-fixed-format-cache` turns it off) (local). A cache written by 1.x is not reused.
- **pytest-xdist 3.8**: `-n auto` counts *physical* cores and "falls back to 1" when it cannot; `-n logical` needs psutil (local). On 2-vCPU runners check what it picked (`test-parallelism.md` §1.1).
- **setup-python v7**: still no caching by default, and no uv support. Use setup-uv for uv projects.
